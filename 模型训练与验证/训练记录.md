## 3. 崩溃/停滞诊断

| 轮次 | 问题 | 根因 |
|------|------|------|
| v1 | E63 崩溃 | person 52k 主导梯度 + Mosaic 全图框冲突 |
| v4 | E98 崩溃 | Mosaic=1.0 + 35k 全图框矛盾梯度 |
| v5 | E25 暂停 | Mosaic=0 安全但慢，未继续 |
| v6 | E47 暂停 | 同 v5，换 YOLOv11s 后仍未突破 |
| v7 Mosaic | E143 崩溃 | garbages 28k 全图框 + Mosaic=0.5 |
| v7 no-Mosaic | E152 崩溃 | garbages 28k 全图框 — 即使 Mosaic=0 也崩溃！ |
| **v8** | **训练中** | **Mosaic=0 + 全图框占 71% — 高概率崩溃，但类间极度均衡** |

### 确定性结论
1. **Mosaic=0 不能防止全图框崩溃** — v7 no-Mosaic 在 E152 崩溃证明了这点
2. **全图框数据是唯一一致的崩溃因子** — 所有崩溃的轮次都有 >28% 的全图框
3. **Mosaic=1.0 能到 0.895 但会崩** — v1 证明上限存在
4. **v8 风险** — 全图框 71% 占比历史最高，崩溃概率极高。但如果不崩，8类均衡度最佳

### 崩溃模式确认

```
全图框占比 ↑ → 崩溃更早、峰值更低

V1:  36% → E52 峰值 0.895 → E63 崩
V4:  63% → E83 峰值 0.828 → E98 崩

V7n: 62% → E67 峰值 0.649 → E152 崩 (20类, no Mosaic)
V8:  71% → E21 峰值 0.808 → E28 崩 (最快崩溃)

结论: 全图框占比越高, 崩溃越急剧。
      V8 E21 就到峰值 0.808 是最快到达的,
      但也因此躲不过 E28 的崩溃。
      全图框数据 — 无论量多少、均衡多好、类数多少 —
      都会最终崩溃。唯一变量是存活多久。
```

### 8.7 V12 未达预期原因

更关键的限制：**pedestrian_pet 和 road_obstacle 共享同源数据、视觉高度混淆，无论什么版本都 ~0.40。** 需要独立数据源来拆分这两个类。
