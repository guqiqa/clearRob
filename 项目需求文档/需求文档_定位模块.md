## 1. 模块定位与职责边界

### 1.1 定位

`localization_engine` 是系统的空间感知基础，承担三个核心职责：
1. **实时 SLAM**：融合 LiDAR 点云 + 里程计 + IMU 进行同步定位与建图
2. **占据栅格地图**：构建并持续更新环境地图，供路径规划使用
3. **tf2 坐标变换**：发布全局坐标系 (map) → 机器人坐标系 (base_link) → 传感器坐标系 (camera/lidar) 的变换关系

### 1.2 职责边界

| 属于本模块 | 不属于本模块 |
|-----------|-------------|
| SLAM 定位（位姿估算） | 里程计原始计算（motion_controller 负责） |
| 占据栅格地图构建与更新 | 点云预处理与障碍物检测（lidar_perception 负责） |
| 回环检测与全局优化 | 路径规划（path_planner 负责） |
| tf2 坐标系广播 | — |

## 2. ROS2 接口规范

### 2.1 Node 信息

| 项目 | 内容 |
|------|------|
| ROS2 Node | `localization_engine` |
| 语言 | C++17（SLAM 计算密集 + tf 实时发布） |
| SLAM 框架 | slam_toolbox（在线异步 SLAM）或自研轻量级 EKF-SLAM |
| 生命周期 | ROS2 Managed Lifecycle |

### 2.2 订阅

| Topic | 消息类型 | QoS | 说明 |
|-------|---------|-----|------|
| `lidar/scan/pointcloud` | `sensor_msgs/msg/PointCloud2` | Sensor Data, KeepLast(5) | 预处理点云（来自 lidar_perception） |
| `motion/odom` | `nav_msgs/msg/Odometry` | Sensor Data, KeepLast(10) | 里程计（来自 motion_controller） |
| `sensor/imu/data` | `sensor_msgs/msg/Imu` | Sensor Data, KeepLast(10) | IMU 数据 |

### 2.3 发布

| Topic | 消息类型 | 频率 | 说明 |
|-------|---------|------|------|
| `localization/pose` | `geometry_msgs/msg/PoseWithCovarianceStamped` | 50Hz | 机器人实时位姿（Map 坐标系） |
| `localization/map/occupancy` | `nav_msgs/msg/OccupancyGrid` | 事件驱动（地图更新时） | 占据栅格地图 |
| `localization/confidence` | `std_msgs/msg/Float32` | 5Hz | 定位置信度 0.0~1.0 |
| `localization/status` | `cleaning_robot_interfaces/msg/VisionStatus` | 1Hz | 定位状态（复用 VisionStatus 格式） |
| `system/heartbeat/localization_engine` | `cleaning_robot_interfaces/msg/Heartbeat` | 1Hz | 心跳 |
| tf | `tf2_msgs/msg/TFMessage` | 50Hz | 坐标变换广播 |

### 2.4 Service

| Service | 类型 | 说明 |
|---------|------|------|
| `localization/get_current_pose` | `cleaning_robot_interfaces/srv/GetCurrentPose` | 查询当前位姿 |
| `localization/request_map` | `cleaning_robot_interfaces/srv/RequestMap` | 请求地图数据（全图或指定 ROI） |

## 3. 功能需求详述

### 3.1 实时 SLAM

**输入融合：**
```
LiDAR 点云 ────→ scan-to-map matching (ICP/NDT)
里程计 ────────→ 运动模型预测 (EKF predict)
IMU ──────────→ 姿态约束 (roll/pitch 绝对参考)
```

**算法流程（每个 LiDAR 帧 10~20Hz）：**
1. **运动预测**：根据里程计增量 + IMU 角速度预测当前位姿先验
2. **扫描匹配**：将当前点云与局部子图（submap）做 scan-to-map 匹配（ICP 迭代 15 次）
3. **位姿更新**：EKF 更新步骤，融合匹配结果 + 里程计约束
4. **地图更新**：根据新位姿将点云投射到占据栅格地图（命中=占据计数+1，射线穿透=空闲计数+1）

**性能要求：**
- 定位更新频率 ≥ 20Hz（scan-to-map 匹配）
- 位姿发布频率 50Hz（EKF 高频插值输出）
- 子图大小：30m × 30m，子图数量 ≤ 10（内存控制）

### 3.2 占据栅格地图

**格式：** `nav_msgs/msg/OccupancyGrid`
- 分辨率: 0.05m/格（默认，可通过参数调整）
- 值域: 0~100（0=空闲，100=占据，-1=未知）
- 地图尺寸: 动态扩展（初始 200m×200m，按需增长）

**更新策略：**
- 增量更新：仅发布变动区域（通过 metadata 的 update_bbox 字段标记）
- 全量发布：首次请求或地图尺寸变化超过 20% 时
- 发布频率限制：≤ 2Hz（避免占用过高带宽）

**动态环境适应：**
- 持续观测到占据计数减少 → 降低占据概率（障碍物清除/移动）
- 临时障碍物（占据 < 3 次观测）→ 不加入地图（滤除动态噪声）

### 3.3 回环检测

**触发条件：** 机器人当前位置与历史轨迹某点距离 < 3m，且时间间隔 > 30s

**处理流程：**
1. 在回环候选区域运行全局 scan-to-map 匹配
2. 匹配得分 > 0.75 时确认回环
3. 全局位姿图优化（pose graph optimization）：调整历史轨迹以消除累积漂移
4. 更新全地图（基于优化后轨迹重新栅格化）
5. 一次性发布更新后的完整 `localization/map/occupancy`

**性能要求：**
- 回环检测模块后台运行，不影响实时定位
- 全局优化耗时 ≤ 3s（局部子图 10 个内）
- 回环期间 `localization/pose` 仍高频发布（使用优化前的临时位姿）

### 3.4 定位置信度评估

**输出：** `localization/confidence (0.0~1.0)`

**计算方法：**
```
confidence = w1 × scan_match_score       # 扫描匹配得分 (0~1)
           + w2 × (1 - min(1.0, covariance_trace / max_covariance))
           + w3 × imu_consistency        # IMU 与里程计一致性
w1=0.5, w2=0.3, w3=0.2
```

**定位置信度阈值：**
- ≥ 0.6：正常（全功能）
- 0.3~0.6：警示（master_controller 降速）
- < 0.3：不可靠（触发 master_controller PAUSED）

### 3.5 tf2 坐标变换

**发布坐标系链：**
```
map ──→ odom ──→ base_link ──→ base_footprint
                      │
                      ├──→ camera_link
                      ├──→ lidar_link
                      └──→ imu_link
```

**变换发布频率：**
- `map → odom`：SLAM 定位修正，50Hz
- `odom → base_link`：里程计积分，100Hz
- `base_link → sensor_*`：静态变换（由 URDF 定义），10Hz

## 4. 配置参数（ROS2 Parameter YAML）

```yaml
localization_engine:
  ros__parameters:
    # 地图
    map_resolution: 0.05                 # 栅格分辨率 (m/格)
    map_init_size_x: 200.0               # 初始地图尺寸 X (m)
    map_init_size_y: 200.0               # 初始地图尺寸 Y (m)
    map_publish_rate_max: 2.0            # 地图最大发布频率 Hz
    
    # SLAM
    slam_algorithm: "slam_toolbox"       # / "ekf_slam" / "graph_slam"
    scan_match_engine: "ICP"             # "ICP" / "NDT"
    icp_max_iterations: 15               # ICP 最大迭代次数
    icp_max_correspondence_dist: 0.5     # ICP 最大对应点距离 (m)
    submap_size: 30.0                    # 子图尺寸 (m)
    max_submaps: 10                      # 最大活跃子图数
    
    # 回环检测
    loop_closure_enabled: true           # 是否启用回环检测
    loop_closure_min_dist: 3.0          # 回环候选最小距离 (m)
    loop_closure_min_interval_s: 30.0   # 回环检测最小时间间隔 (s)
    loop_closure_match_threshold: 0.75  # 回环匹配确认阈值
    
    # EKF
    ekf_process_noise_xy: 0.05
    ekf_process_noise_yaw: 0.02
    ekf_odom_noise_xy: 0.02
    ekf_odom_noise_yaw: 0.01
    
    # 置信度
    confidence_scan_match_weight: 0.5
    confidence_covariance_weight: 0.3
    confidence_imu_weight: 0.2
    max_covariance_trace: 0.5            # 协方差迹上限
    
    # 性能
    localization_rate: 50.0              # 位姿发布频率 Hz
    scan_match_rate: 20.0                # 扫描匹配频率 Hz
```

## 5. 异常处理

| 故障场景 | 检测方式 | 响应行为 |
|----------|----------|----------|
| LiDAR 点云超时 | `lidar/scan/pointcloud` > 2s 无帧 | 纯里程计推算（open-loop），confidence 快速衰减 |
| 扫描匹配持续失败 | scan_match_score < 0.3 持续 10s | 发布 status=1 降级，confidence 降至 0.1；如果 > 30s 转 status=2（定位丢失） |
| 里程计异常跳跃 | 单帧位移 > 2m（物理不可能） | 丢弃该帧里程计，日志 WARN |
| 地图内存超限 | 栅格数量 > 100M | 停止地图扩展，以机器人当前位置为中心截取 200m×200m 窗口（丢掉最远区域） |
| 回环检测误匹配 | 回环匹配 + 全局优化后位姿跳变 > 1m | 拒绝本次回环，日志 WARN |

## 6. 开发里程碑

| 阶段 | 内容 | 交付物 |
|------|------|--------|
| M1: 基础定位 | scan-to-map 匹配 + EKF 融合 + pose 发布 | 实时位姿输出 |
| M2: 建图 | 占据栅格地图构建 + 动态更新 | 地图可请求 |
| M3: tf2 | 完整坐标系变换链广播 | 坐标系统一 |
| M4: 回环 | 回环检测 + 全局优化 | 累积漂移 < 0.5m/km |
| M5: 置信度 | 定位置信度评估 + 降级通知 | master_controller 可感知定位质量 |
