## 1. 模块定位与职责边界

### 1.1 定位

`cleaning_actuator` 是系统的清扫执行机构，负责主刷/边刷控制、吸力调节、洒水量控制、尘满检测。接收主控调度的清扫策略指令，基于视觉反馈（垃圾信息+清洁度）自适应调节清扫参数。

### 1.2 职责边界

| 属于本模块 | 不属于本模块 |
|-----------|-------------|
| 主刷/边刷启停与转速控制 | 何时清扫、清扫哪种策略（master_controller 决定） |
| 吸力自适应调节 | 垃圾检测与分类（vision_detector 负责） |
| 洒水量比例控制 | 清洁度评估（vision_detector 负责） |
| 尘满检测（传感器读数 + 告警） | — |
| 清扫面积与垃圾量统计 | — |

## 3. 功能需求详述

### 3.1 清扫策略执行

**策略对照：**

| 策略 (strategy) | 主刷转速 | 边刷转速 | 吸力 | 洒水量 | 适用场景 |
|-----------------|----------|----------|------|--------|----------|
| COVER (0) | 0.7 | 0.7 | 0.6 | 0.3 | 全场覆盖清扫，保守参数以节能 |
| SPOT (1) | 1.0 | 1.0 | 1.0 | 0.8 | 定点密集清扫（检测到垃圾密集区），全功率 |
| TRACK (2) | 0.8 | 0.5 | 0.9 | 0.5 | 跟随垃圾路径清扫，强吸力为主 |
| IDLE (3) | 0.0 | 0.0 | 0.0 | 0.0 | 待命，所有清扫机构停止 |

**参数说明：** 所有参数为 0.0~1.0 的比例值，对应硬件最大能力的百分比。

**strategy 优先于 CleanStrategy 中的 suction_power/water_amount/brush_speed 字段**：当 strategy 非 IDLE 时使用策略默认参数；CleanStrategy 中的具体字段用于微调（如 special_case=true 时用自定义值覆盖策略默认值）。

### 3.2 垃圾类别感知调节

基于 `vision/detect/list` 中的垃圾类别动态微调清扫参数（覆盖策略默认值）：

| 检测到的主要垃圾类别 | 调节动作 |
|---------------------|----------|
| recyclable（塑料瓶/易拉罐/大纸箱） | 提高主刷转速 + 10%，增大吸力 + 20% |
| kitchen_waste（果皮/食物残渣） | 先吸后拖模式：吸力 1.0 → 等待 2s → 洒水量 + 15% + 刷盘启动 |
| hazardous（电池/药品） | 停止正常清扫，转入单独收集模式（降低吸力 0.3 以防破损，发布 WARN 告警） |
| other_waste（烟头/纸屑/塑料袋） | 正常参数（使用策略默认值） |
| green_waste（落叶/枯枝） | 增大吸力 + 15%，降低洒水量（落叶无需洒水） |
| stain（污渍/小面积积水） | 洒水量 1.0 + 主刷转速 0.9（重拖），不启动吸力（避免吸水损坏） |

**调节模式切换延迟：** ≤ 500ms（从视觉检测到新垃圾类别到清扫参数切换完毕）

### 3.3 尘满检测

**传感器：** 集尘箱红外对射传感器 + 滤网压差传感器

**输出：** `cleaning/status/dust_full`

| 条件 | is_full | dust_level | 说明 |
|------|---------|------------|------|
| 红外被遮挡（垃圾溢出） | true | 1.0 | 立即通知 master_controller，触发 RETURN |
| 滤网压差 > 额定 × 1.5 | true | dust_level（根据压差线性映射） | 严重影响吸力，触发 RETURN |
| 红外未遮挡 + 压差正常 | false | 压差比（0~1） | 正常 |

### 3.4 刷盘状态监测

**输出：** `cleaning/status/brush`（1Hz）

| 字段 | 说明 |
|------|------|
| main_brush_rpm | 主刷实际转速 RPM |
| side_brush_rpm | 边刷实际转速 RPM |
| main_brush_wear | 主刷磨损率 0.0~1.0（基于累计运行时间 + 堵转次数估算） |
| side_brush_wear | 边刷磨损率 |

**磨损告警：** brush_wear ≥ 0.8 时触发 WARN（需更换刷盘），通过 system/alert 发布。

### 3.5 清扫统计

**已清扫面积** `cleaning/stats/area`：
- 每 5s 发布一次累计值
- 面积 = 清扫宽度 × 行驶距离 × 覆盖效率系数 (0.85)
- 仅当清扫机构处于非 IDLE 状态时累加

**垃圾收集量** `cleaning/stats/waste_volume`：
- 基于集尘箱满度传感器线性估算
- 单位：L
- 每次 execute_cleanup 开始时归零

## 4. Action Server: execute_cleanup

### 4.1 Goal（接收）

| 字段 | 类型 | 说明 |
|------|------|------|
| strategy | uint8 | 0=COVER 1=SPOT 2=TRACK |
| duration_s | float32 | 清扫持续时长 (s)，0=持续到收到取消 |

### 4.2 Feedback（发送）

| 字段 | 类型 | 说明 |
|------|------|------|
| elapsed_s | float32 | 已执行时长 (s) |
| cleanliness_current | float32 | 当前清洁度（来自 vision/detect/cleanliness） |
| waste_instant_l | float32 | 瞬时垃圾收集增量 (L) |

### 4.3 Result（返回）

| 字段 | 类型 | 说明 |
|------|------|------|
| success | bool | 是否成功完成 |
| actual_duration | float32 | 实际清扫时长 (s) |
| waste_collected_l | float32 | 本次任务垃圾收集量 (L) |
| avg_cleanliness_before | float32 | 清扫前平均清洁度 |
| avg_cleanliness_after | float32 | 清扫后平均清洁度 |

### 4.4 执行期间逻辑

```
进入 execute_cleanup:
  1. 记录 initial_cleanliness（当前清洁度）
  2. 按 strategy 启动清扫机构
  3. 循环（每 1Hz）：
     a. 发布 Feedback(elapsed_s, cleanliness, waste)
     b. 根据 vision/detect/list 微调清扫参数（见 3.2）
     c. 若 duration_s > 0 且 elapsed ≥ duration_s → 跳出
     d. 若 dust_full.is_full → 提前结束，Result(success=false)
     e. 若收到取消 → 停止机构，Result(actual_duration)
  4. 停止清扫机构
  5. 记录 final_cleanliness
  6. 返回 Result(success=true, actual_duration, waste_collected, avg_cleanliness_before, avg_cleanliness_after)
```

## 5. 配置参数（ROS2 Parameter YAML）

```yaml
cleaning_actuator:
  ros__parameters:
    # 清扫宽度
    cleaning_width: 0.8                  # 清扫机构实际覆盖宽度 (m)
    
    # 默认清扫参数（策略默认值，0.0~1.0）
    strategy_defaults:
      cover:
        main_brush: 0.7
        side_brush: 0.7
        suction: 0.6
        water: 0.3
      spot:
        main_brush: 1.0
        side_brush: 1.0
        suction: 1.0
        water: 0.8
      track:
        main_brush: 0.8
        side_brush: 0.5
        suction: 0.9
        water: 0.5
    
    # 垃圾类别调节补偿
    class_compensation:
      recyclable:      { brush: 0.10, suction: 0.20, water: 0.00 }
      kitchen_waste:   { brush: 0.15, suction: 0.00, water: 0.15, mode: "suck_then_mop" }
      hazardous:       { brush: 0.00, suction: -0.70, water: 0.00, mode: "separate_collect" }
      other_waste:     { brush: 0.00, suction: 0.00, water: 0.00 }
      green_waste:     { brush: 0.00, suction: 0.15, water: -0.20 }
      stain:           { brush: -1.00, suction: -1.00, water: 1.00, mode: "mop_only" }
    
    # 物理阈值
    dust_full_ir_threshold: 1            # 红外遮挡 = 1
    filter_pressure_ratio_max: 1.5       # 滤网压差最大倍数
    brush_wear_warn_threshold: 0.8       # 刷盘磨损告警阈值
    
    # 时序
    param_switch_delay_ms: 500           # 清扫参数切换延迟 (ms)
    kitchen_suck_duration_s: 2.0         # 厨余垃圾先吸时长
```

## 6. 异常处理

| 故障场景 | 检测方式 | 响应行为 |
|----------|----------|----------|
| 主刷堵转 | 主刷电流 > 额定 × 2 + 转速 < 0.1×目标 持续 3s | 停止主刷，尝试反转 2s 后再正转，失败则停止并向 master_controller 告警 |
| 边刷堵转 | 同上 | 仅停止该边刷，不影响主刷和吸力（可降级工作） |
| 吸力电机过热 | 电机温度 > 85°C | 吸力降至 50%，60s 后若仍过热降至 0（停止吸力） |
| 水箱空 | 水位传感器 < 5%（或无传感器则基于洒水累计时间估算） | 洒水量降至 0，发布 WARN"water_empty" |
| 尘满 | 红外遮挡 或 滤网压差异常 | 触发 is_full=true → master_controller 决定 RETURN；同时降低吸力 0.1 防止二次污染 |

## 7. 开发里程碑

| 阶段 | 内容 | 交付物 |
|------|------|--------|
| M1: 基础启停 | 主刷/边刷/吸力/洒水 四路独立控制 | 清扫机构可控 |
| M2: 策略联动 | COVER/SPOT/TRACK 策略切换 + 视觉反馈调节 | 自适应清扫 |
| M3: 监测 | 尘满 + 刷磨损 + 水箱空 | 状态监测齐全 |
| M4: Action | execute_cleanup Server + 进度反馈 | 清扫 Action 可用 |
| M5: 统计 | 面积 + 垃圾量累计 | 清扫统计报表 |
