## 1. 模块定位与职责边界

### 1.1 定位

`path_planner` 是导航系统的核心模块，承担三个职责：
1. **全局覆盖路径规划**：接收清扫区域 + 地图 → 计算最优全覆盖路径
2. **路径跟踪控制**：实时订阅位姿 → 计算横向/航向偏差 → 输出操控指令（线速度/角速度）
3. **局部避障重规划**：接收融合模块避障决策 → 执行绕行/等待/减速

### 1.2 职责边界

| 属于本模块 | 不属于本模块 |
|-----------|-------------|
| 覆盖路径计算（Boustrophedon + TSP） | 路径执行/底盘控制（motion_controller 负责） |
| 路径跟踪偏差解算 → 操控指令 | 操控指令仲裁（master_controller 负责） |
| 局部避障重规划（绕行/等待/减速） | 是否需要避障的判定（fusion_engine 负责） |
| Action Server: navigate_to_goal | — |

## 3. 功能需求详述

### 3.1 全局覆盖路径规划

**输入：** `master/task/area`（区域多边形 boundary + 覆盖次数 + 重叠率）+ `localization/map/occupancy`（占据栅格地图）

**输出：** `planner/output/path`（waypoints 序列 + 总长度 + 路径序号）

**算法：**
1. **Boustrophedon 分解**（牛耕式覆盖）：
   - 将区域多边形沿主方向（长边方向）分解为若干条带
   - 条带宽度 = 清扫宽度 × (1 - overlap_ratio)
   - 每条条带生成往返路径点（U 形掉头连接相邻条带）
2. **边界回形**：沿区域边界生成一圈补充路径，覆盖边缘
3. **多区域 TSP**：多个区域时，计算区域间的访问顺序（最近邻 + 2-opt 优化），最小化转移路径
4. **路径点平滑**：对转折点应用 3 次 B-spline 平滑（转弯半径 ≥ 0.5m）

**输出规格：**
- 路径点间距 ≤ 0.1m（稠密以保证跟踪精度）
- 每个 waypoint 包含 PoseStamped（Map 坐标系）
- Path.sequence 每次规划递增，供 master_controller 辨别新旧路径

### 3.2 路径跟踪控制

**触发条件：** `master/task/mode(mode=CRUISE or CLEAN)` + 路径已发布

**输入：**
- `localization/pose`：机器人当前位姿 (x, y, θ)
- 当前目标路径点：path.waypoints 中最近的前瞻点

**处理流程（20Hz 循环）：**
```
1. 查找前瞻点（lookahead）：沿路径从当前位置向前搜索 distance = lookahead_distance
2. 计算横向偏差 cross_track_error：当前位置到前瞻路径段的最短距离
3. 计算航向偏差 heading_error：当前航向角 vs 路径切线方向角
4. 纯追踪（Pure Pursuit）控制器：
       angular_velocity = 2 * linear_velocity * sin(heading_error) / lookahead_distance
                           + k_cross * cross_track_error
5. 线速度控制：
       linear_velocity = target_velocity * (1 - min(1.0, |angular_velocity| / max_angular))
6. 发布 planner/cmd/maneuver(Twist)
```

**控制器参数：**
- `lookahead_distance`（前瞻距离）：`min_lookahead + current_velocity * lookahead_gain`
  - 默认：0.5m ~ 2.0m（随速度动态调整）
- `k_cross`（横向偏差增益）：0.8
- `target_velocity`：CRUISE 模式 0.8 m/s，CLEAN 模式 0.3 m/s

**到达判定：** 当距离最终路径点 < target_tolerance（默认 0.1m）+ 航向偏差 < 5° + 线速度 < 0.05 m/s 时判定到达。

### 3.3 局部避障重规划

**触发条件：** 收到 `fusion/obstacle/decision`

**处理流程：**

| fusion/obstacle/decision.action | path_planner 动作 | 状态 |
|------|------|------|
| DETOUR（绕行） | 在障碍物位置生成绕行路径：基于当前位姿 → 侧移 detour_offset 距离的中间点 → 回归原路径最近安全点。使用 TEB（Timed Elastic Band）局部规划器生成平滑绕行轨迹 | REPLANNING → EXECUTING |
| WAIT（等待） | 暂停路径跟踪（保持原地），发布零速 maneuver。持续订阅 fusion/obstacle/decision，action 变为 PASS 后恢复跟踪 | EXECUTING（暂停子状态） |
| SLOW（减速） | 将 target_velocity 临时降至 slow_ratio × 原速度。保持路径不变。障碍物区域通过后恢复原速度 | EXECUTING（减速子状态） |
| PASS（可通行） | 正常路径跟踪，无需额外处理 | EXECUTING |

**速度恢复：** DETOUR 完成后恢复 target_velocity；SLOW 通过障碍物区域后自动恢复原 target_velocity。

**冲突处理：** 若同时有多个避障决策（多个障碍物），取最保守策略（WAIT > DETOUR > SLOW > PASS）。

### 3.4 多区域清扫顺序优化

**输入：** 多个 TaskArea（App 一次下发多个区域）

**处理：**
1. 为每个区域独立执行 Boustrophedon 覆盖规划
2. 以机器人当前位置为起点，用最近邻 + 2-opt 求解区域间访问顺序 TSP
3. 输出完整路径序列（区域1 路径 + 转移路径 + 区域2 路径 + ... + 转移路径 + 区域N 路径）
4. 路径顺序下发给 master_controller 作为 Path 消息

## 4. Action Server: navigate_to_goal

### 4.1 Goal（接收）

| 字段 | 类型 | 说明 |
|------|------|------|
| target_pose | geometry_msgs/PoseStamped | 目标位姿（Map 坐标系） |
| target_tolerance | float32 | 到达容差 m（默认 0.1） |
| timeout_s | float32 | 超时秒数（0=无超时） |

### 4.2 Feedback（发送）

| 字段 | 类型 | 说明 |
|------|------|------|
| progress | float32 | 进度 0.0~1.0 |
| distance_to_goal | float32 | 当前距目标点距离 (m) |
| estimated_remaining_s | float32 | 预计剩余时间 (s) |

### 4.3 Result（返回）

| 字段 | 类型 | 说明 |
|------|------|------|
| success | bool | 是否成功 |
| final_distance | float32 | 最终距目标距离 (m) |
| path_length | float32 | 实际行驶路径长度 (m) |

### 4.4 取消处理

- 收到取消请求时，立即中止当前路径跟踪，发送零速 maneuver
- 返回 Result(success=false, final_distance=当前距目标距离)
- 清理当前规划的路径数据

## 5. 状态机

```
    ┌──────┐
    │ IDLE │ ← 无任务
    └──┬───┘
       │ 收到 master/task/area 或 Action Goal
       ↓
    ┌─────────┐
    │PLANNING │ ← 路径计算中
    └──┬──────┘
       │ 规划成功
       ↓
    ┌─────────┐
    │ READY   │ ← 路径就绪，等待 master_controller 调用 follow_path
    └──┬──────┘
       │ master/task/mode = CRUISE/CLEAN
       ↓
    ┌──────────┐
    │EXECUTING │ ← 路径跟踪中 (20Hz 操控指令输出)
    └──┬──┬───┘
       │  │ fusion/obstacle/decision = DETOUR/WAIT/SLOW
       │  └──→ ┌───────────┐
       │       │REPLANNING  │ ← 局部重规划
       │       └──┬────────┘
       │          │ 重规划完成 → 回 EXECUTING
       │ 到达目标点 or 跟踪完成
       ↓
    ┌──────────┐
    │COMPLETED │ → 回归 IDLE
    └──────────┘
    
    任意状态 + 规划失败（无可行路径） → ┌─────────┐
                                       │ BLOCKED │ → 等待 master 重新下发
                                       └─────────┘
```

**状态发布：** `planner/status/state` 以 5Hz 频率发布当前状态码和描述文本。

## 6. 配置参数（ROS2 Parameter YAML）

```yaml
path_planner:
  ros__parameters:
    # 全局覆盖规划
    cleaning_width: 0.8                  # 清扫宽度 (m)，取决于清扫机构
    default_overlap_ratio: 0.1           # 默认路径重叠率
    waypoint_spacing: 0.1                # 路径点间距 (m)
    min_turn_radius: 0.5                 # 最小转弯半径 (m)
    
    # 路径跟踪
    lookahead_min: 0.5                   # 最小前瞻距离 (m)
    lookahead_max: 2.0                   # 最大前瞻距离 (m)
    lookahead_gain: 0.8                  # 前瞻距离速度增益
    k_cross_track: 0.8                   # 横向偏差增益
    k_heading: 1.0                       # 航向偏差增益（内部）
    target_velocity_cruise: 0.8          # 巡航线速度 m/s
    target_velocity_clean: 0.3           # 清扫线速度 m/s
    controller_rate: 20.0                # 路径跟踪控制频率 Hz
    
    # 到达判定
    position_tolerance: 0.1              # 位置容差 (m)
    heading_tolerance_deg: 5.0           # 航向容差 (°)
    stop_velocity: 0.05                  # 停止判定线速度 (m/s)
    
    # 避障重规划
    teb_optimization_iterations: 3       # TEB 优化迭代次数
    teb_min_obstacle_dist: 0.3           # 最小障碍物距离 (m)
    
    # 性能
    planning_timeout_s: 10.0             # 单次规划超时 (s)
    max_replanning_attempts: 5           # 最大重规划尝试次数
```

## 7. 异常处理

| 故障场景 | 检测方式 | 响应行为 |
|----------|----------|----------|
| 无可行路径 | 规划算法返回空路径 | 状态 = BLOCKED；master_controller 重新设定区域或放弃 |
| 定位丢失 | `localization/pose` 超时 > 1s | 暂停路径跟踪，发布零速 maneuver，等待定位恢复 |
| 路径跟踪偏差过大 | cross_track_error > 0.5m 持续 2s | 停止路径跟踪，重新请求规划（从当前位置重新规划到原目标） |
| 重规划失败超限 | 连续失败 > max_replanning_attempts | 状态 = BLOCKED；发布零速 maneuver |
| 避障决策冲突 | 多障碍物同时触发不同决策 | 取最保守策略（WAIT > DETOUR > SLOW > PASS） |
| 规划超时 | 规划耗时 > planning_timeout_s | 状态 = BLOCKED；中止规划 |

## 8. 关键交互序列

### 8.1 覆盖清扫任务

```
master_controller → master/task/area → path_planner
                                         │
                                    Boustrophedon 分解
                                    (IDLE → PLANNING)
                                         │
                                    planner/output/path → master_controller
                                    planner/status/state = READY
                                         │
master_controller → motion/follow_path
master/task/mode = CRUISE               │
                                         ↓
localization/pose ──→ path_planner (20Hz 循环)
                         │
                    Pure Pursuit 控制
                         │
                    planner/cmd/maneuver (Twist) → master_controller 仲裁
                         │
                    [若 fusion/obstacle/decision = DETOUR]
                         │
                    TEB 局部绕行规划 (EXECUTING → REPLANNING → EXECUTING)
                         │
                    planner/cmd/maneuver (修正后)
                         │
                    ... 持续跟踪直到路径终点 ...
                         │
                    planner/status/state = COMPLETED
```
