## 0. 系统四层架构

整个机器人软件按**职责分层**：参数 → 公式 → 控制算法 → 主程序编排。调整硬件参数时，明确该改哪一层、影响什么。

```
┌────────────────────────────────────────────────────────────────┐
│ ① 配置层 — 记录全部设备/部件参数                                    │
│                                                                │
│   phase1_params.yaml    ← 运行时权威（launch 加载，覆盖默认值）      │
│     chassis_core: {...}  ← 底盘控制全部参数（90+ 项）              │
│     imu_driver/rtk_driver/remote_driver: {...}                  │
│   config.py             ← 代码默认值（被 yaml 覆盖）               │
│     WHEEL_RADIUS_M, TRACK_WIDTH_M, MOTOR_DIRS, ...             │
└────────────────────────────────────────────────────────────────┘
                              │ 读取
┌────────────────────────────────────────────────────────────────┐
│ ② 函数库 — 通用公式/协议（cleaning_robot_common 包）              │
│                                                                │
│   kinematics.py      ← 差速运动学、里程计积分、四元数转换          │
│   can_protocol.py    ← CAN 帧构造/解析（OID FOC 协议）           │
│   wheel_speed_loop.py ← 纯 Python 速度环（仿真/参考，生产不用）     │
└────────────────────────────────────────────────────────────────┘
                              │ 调用
┌────────────────────────────────────────────────────────────────┐
│ ③ 控制核心 — 同事实调算法（chassis_core，C++ 编译 .so）           │
│                                                                │
│   chassis_core.cpp    ← 转向模型/原地旋转/航向保持/换向/档位/轮速PI │
│   pybind11 绑定         ← Python 可调用的 ChassisCore 类          │
└────────────────────────────────────────────────────────────────┘
                              │ 编排
┌────────────────────────────────────────────────────────────────┐
│ ④ 主程序 — ROS2 驱动节点                                         │
│                                                                │
│   chassis_node.py   ← 调 ②函数库 + ③控制核心 + CAN/IMU I/O       │
│   imu_node.py       ← 独立实现（未接 ②，历史遗留）                │
│   remote_node.py    ← 独立实现（未接 ②）                          │
│   rtk_node.py       ← 独立实现（未接 ②）                          │
│   bridge_node.py    ← 调 ②config + 遥控→intent 翻译               │
└────────────────────────────────────────────────────────────────┘
```

### 0.1 各层职责与依赖

| 层 | 归属 | 内容 | 被谁使用 |
|----|------|------|---------|
| **① 配置层** | `phase1_params.yaml` + `config.py` | 全部设备/部件参数 | 所有节点 + C++ 核心 |
| **② 函数库** | `cleaning_robot_common` 包 | 通用公式：运动学、CAN协议、速度环（参考） | `chassis_node`、`bridge_node` |
| **③ 控制核心** | `chassis_core` 包（C++ .so） | 同事实调控制算法 | `chassis_node` |
| **④ 主程序** | 各 driver/bridge 节点 | ROS2 编排、订阅/发布、硬件 I/O | —（系统入口） |

### 0.2 参数影响面（改哪个参数影响什么）

**重要结论**：`wheel_radius`/`track_width` 只影响**里程计**（导航定位），**不影响控制**。同事控制是纯 RPM 直控，不依赖轮径轮距。

| 想调整... | 改哪层 | 具体参数 | 影响 |
|-----------|--------|---------|------|
| 里程计不准（定位漂移） | ①配置 | `wheel_radius`、`track_width` | `/odom` 位移/角速度 |
| 车太快/太慢（遥控手感） | ①配置 | `run_rpm`、`gear_*_run_rpm` | 电机目标 RPM |
| 转弯过猛/过缓 | ①配置 | `turn_max_rpm`、`rotate_rpm` | 转弯半径 |
| 电机方向反了 | ①配置 | `motor_dirs`（cal_dirs 自动校准） | 前后/左右 |
| 加减速灵敏度 | ①配置 | `speed_accel_rpm_s`、`speed_decel_rpm_s` | 加速/减速斜坡 |
| 启动卡顿/无力 | ①配置 | `wheel_start_*`、`wheel_speed_kp/ki` | 启动斜坡/速度环 |
| 直线跑偏 | ①配置 | `heading_kp/kd`、`heading_*` | 航向纠偏 |

> 调参路径：`cal_dirs.py --basics`（基础参数）→ `cal_dirs.py --apply`（方向）→ 改 `phase1_params.yaml`（手感）→ 重启底盘。

### 0.3 模块接入现状

| 节点 | 接入②函数库 | 说明 |
|------|:---:|------|
| `chassis_node` | ✅ | 调 config + kinematics + can_protocol + ③C++核心 |
| `bridge_node` | ✅ | 调 config（Topic/常量） |
| `imu_node` | ❌ | 独立声明参数（校准系数在文件内） |
| `remote_node` | ❌ | 独立声明参数（SBUS 常量在文件内） |
| `rtk_node` | ❌ | 独立声明参数（NMEA 在文件内） |

> imu/remote/rtk 未接入 ② 是**历史遗留**（先有节点后有 common 库），不影响功能，后续可收敛。

## 1. 架构总览

```
                     ┌────────────────────────────────────────────┐
  操控方式（可插拔）  │          chassis_driver (Python shell)       │
 ─────────────      │  ────────────────────────────────────────   │
 遥控器 (SBUS) ──┐  │  /cmd_vel ─┐                                │
 App (UDP)    ──┼─►│          仲裁(estop>intent>cmd_vel>failsafe)  │
 自主导航       ──┘  │  /chassis/intent ─┘        │                │
                     │  /imu/data ──→ yaw 积分 ──►│                │
                     │                           ▼                │
                     │   ┌─────────────────────────────┐          │
                     │   │   C++ chassis_core (.so)     │          │
                     │   │   (同事 WheelPID V2 原样逻辑)  │          │
                     │   │   转向模型/原地旋转/航向保持/   │          │
                     │   │   换向保持/档位/轮速PI+启动斜坡 │          │
                     │   └─────────────────────────────┘          │
                     │              │ 电流指令                      │
                     │              ▼                             │
                     │   python-can → can0 → OID FOC 电机 ×4        │
                     └────────────────────────────────────────────┘
```

**职责边界：**

| 层 | 归属 | 内容 |
|----|------|------|
| C++ 核心 | `chassis_core` 包 | 全部控制逻辑（同事实调成果 100% 保留），纯计算、无 I/O、单线程同步 |
| Python 壳 | `chassis_driver` 节点 | 所有 ROS2 + 硬件 I/O：订阅/发布、意图仲裁、CAN 调度、IMU yaw 积分、里程计 |
| 输入 | `/chassis/intent` | 主要控制接口（JSON）；`/cmd_vel` 为兼容接口（Twist） |
| 输出 | `can0` | 电流指令（10mA 单位，motor_dir 已应用） |

**为什么 C++ + Python 壳：**
- 同事程序是 C++，在实车验证过完整手感（转向、原地转、直线保持、换向）
- pybind11 零序列化开销，控制周期 50ms（20Hz）每次 tick 输入 ~60 字节
- 复用现有 Python 生态：`can_protocol.py` 帧构造、`python-can`、`imu_driver`、`remote_driver`
- 意图接口让遥控/App/自主导航可插拔

## 2. 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| IPC | pybind11 (.so) | 同步调用、零拷贝、C++ 逻辑逐字节保留 |
| CAN 归属 | Python 壳独占 | 避免双开 socket 竞争；复用已验证的 can_protocol |
| IMU 来源 | 订阅 `/imu/data`（QMI8658） | 硬件无关；替代 C++ 原版直接读 IIO sysfs |
| 配置源 | ROS2 YAML（`chassis_core:` 段） | 单一事实源；改参数不重编译 |
| 控制接口 | intent 主题 + cmd_vel 兼容 | 遥控/App/自主导航统一入口 |
| 速度环 | C++ 核心内 | 启动斜坡 + PI 原样运行（含 feedback_generation 门控） |

## 3. pybind11 接口规范

```python
import chassis_core

core = chassis_core.ChassisCore(config_dict)   # dict 键见第 5 节

# 单控制周期（20Hz 调用）
currents, safety, reason = core.tick(
    throttle,          # float -1..1 （连续；RC 离散 ±1，cmd_vel 按比例）
    steering,          # float -1..1
    gear,              # str "LOW" | "MID" | "HIGH"
    mower_on,          # bool
    estop,             # bool → failsafe
    wheel_rpm,         # list[4] 物理轮速（FL,RL,FR,RR 顺序）
    wheel_valid,       # list[4] 反馈新鲜度
    wheel_gen,         # list[4] 反馈代数（新反馈递增 → new_feedback 门控）
    imu_yaw_deg,       # float 积分的航向角（度）
    imu_yaw_rate_dps,  # float 瞬时角速度（度/秒）
)
# 返回:
#   currents : list[4] CAN 电流指令（10mA 单位，motor_dir 已应用，可直接发送）
#   safety   : bool  超速/启动超时/丢反馈 安全锁
#   reason   : str

core.set_gear("MID")          # 切换档位（更新 run_rpm/turn_max_rpm）
core.stop_all()               # 硬停，返回 0 电流
core.reset_safety()           # 清安全锁（throttle 回中）
core.set_imu(yaw, rate, valid)
core.set_wheel_feedback(rpm, valid, gen)
```

**关键点：**
- `wheel_gen` 必须在新 CAN 反馈时递增（Python 壳在收到转速响应时 `generation[cid] += 1`）——这是 C++ 核心判断"新反馈"的门控，缺失会导致启动确认/堵转检测失效（此前 Python 移植卡顿的根因之一）。
- `motor_dirs` 已应用在返回的电流中，Python 壳直接发 CAN。

## 4. C++ 核心保真的控制逻辑

### 4.1 转向模型（skid-steer + 内轮约束）

```
gain = (1 - turn_inner_ratio) / (1 + turn_inner_ratio)   # 内轮比例控制
left  = throttle - steering * gain
right = throttle + steering * gain
peak = max(1, |left|, |right|);  left /= peak;  right /= peak
left_rpm  = round(left  * rpm_limit)
right_rpm = round(right * rpm_limit)
```

- `turn_inner_ratio = -0.20`：转弯时内轮减速约束，防止内轮倒拖
- `arc_turn_blend_ms = 700`：直行→转向差速 700ms 渐变，转向平顺起步

### 4.2 原地旋转（throttle=0 + steering≠0）

- `rotate_neutral_hold_ms = 150`：先保持 150ms 过滤摇杆抖动
- `rotate_factory_current_control_enable`：直接发 5.00A 电流（rotate_max_current=500×10mA）破静摩擦
- `rotate_speed_guard`：轮速 >25rpm 时先等轮停（1.2s 超时）

### 4.3 航向保持（IMU yaw PID）

- 直线指令（throttle≠0 且 steering=0）时锁定当前 yaw 为目标
- `correction = Kp*error + Ki*integral - Kd*rate + trim`，限幅 ±5rpm
- 转向指令重置目标（`heading_reset_steering_hold_ms=500` 防抖）
- `direction_change_post_hold_ms=1000`：换向后 1s 内限制纠偏幅度

### 4.4 换向保持（前后换向先刹车）

- 检测到方向反转（throttle 符号变化）→ 进入保持态
- 等 4 轮都 <5rpm（或 1.5s 超时）→ 再执行反转
- 防"前进→后退"瞬间反转冲击

### 4.5 档位（gear）

| 档位 | run_rpm | turn_max_rpm |
|------|:---:|:---:|
| LOW | 70 | 70 |
| MID | 120 | 100 |
| HIGH | 140 | 100 |

### 4.6 轮速环（current 模式软件 PI）

```
启动斜坡:  55mA 起, 每 200ms +2mA, 上限 70mA
确认启动:  measured ≥ 2rpm (new_feedback 门控, 1 次确认)
稳态 PI:   ff + Kp*error + Ki*integral, 限幅 ±35mA
堵转:      measured < 1rpm 持续 3 次 → 重启启动
安全锁:    超速 >120rpm / 启动超时 7s / 丢反馈 >1s → latch 停机
```

## 6. 与旧 Python 移植（wheel_speed_loop.py）的差异

| 方面 | 旧 Python 移植 | 新 C++ 核心 |
|------|--------------|------------|
| 反馈门控 | 无（每 tick 用旧值重判） | `feedback_generation` 门控，只处理新反馈 |
| 转向模型 | 标准差速 v±w·L/2 | 内轮约束 + 弧线过渡 + 归一化 |
| 原地旋转 | 无 | 5A 工厂电流原地转 |
| 航向保持 | 无（靠 MOTOR_GAINS） | IMU yaw PID 闭环纠偏 |
| 换向保持 | 无 | 先刹车再反转 |
| 档位 | 无 | LOW/MID/HIGH |
| 启动卡顿 | 有（手调 catch-up） | 原版逻辑（实测不卡顿） |

**启动卡顿根因消除**：Python 移植缺 `new_feedback` 门控，启动确认时机偏移导致切换瞬间 PI 反向急刹。C++ 核心保留原版门控，与同事实车一致。
