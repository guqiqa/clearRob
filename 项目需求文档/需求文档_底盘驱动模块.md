## 1. 模块定位

`chassis_driver` 是机器人与 OID FOC 无刷电机之间的 ROS2 桥接节点，通过 SocketCAN 接口直接控制 5 台电机（4 台行走 + 1 台刀盘），并将电机转速反馈转换为里程计数据。

本模块替代 V2.x 中的 `motion_controller`——因为实际硬件是 CAN 直驱，不需要抽象的速度→电机映射层。

---

## 2. 硬件接口

### 2.1 CAN 总线

| 参数 | 值 |
|------|------|
| 接口 | `can0` (SocketCAN) |
| 波特率 | 500 Kbps |
| 帧类型 | 标准数据帧 (11-bit ID) |
| Python 库 | `python-can` |

### 2.2 电机 CAN ID

| CAN ID | 电机 | 功能 |
|:---:|------|------|
| `001` | 左后轮 | 行走驱动 |
| `002` | 左前轮 | 行走驱动 |
| `003` | 右后轮 | 行走驱动 |
| `004` | 右前轮 | 行走驱动 |
| `005` | 刀盘 | 切割/清扫 (二期) |

### 2.3 CAN 帧格式

**电流控制帧 (DLC=3):**
```
DATA[0] = 0x01          # 电流控制模式
DATA[1] = 高 8 位        \
DATA[2] = 低 8 位        /  int16 电流值 (10mA/unit), 正=正转, 负=反转
```

**心跳帧 (DLC=1):**
```
DATA[0] = 0x00          # 心跳，需周期发送维持通信
```

**查询帧 (DLC=2):**
```
DATA[0] = 0x0F          # 查询指令
DATA[1] = 0x01          # 查询码 01 = 转速 (erpm)
```

**查询响应帧 (DLC=6):**
```
DATA[0] = 0x0F          # 查询指令回显
DATA[1] = 0x01          # 查询码回显
DATA[2:6] = int32       # 电机转速 (erpm)
```

### 2.4 里程计参数

| 参数 | 符号 | 值 | 单位 |
|------|------|------|------|
| 电机磁极对数 | `pole_pairs` | **10** (20 极电机) | — |
| 减速比 | `gear_ratio` | **5.2:1** | — |
| 轮半径 | `wheel_radius` | 0.08 | m (160mm/2) |
| 轮距 | `track_width` | 0.53 | m |

**里程计公式（含减速比）:**
```python
def erpm_to_linear_velocity(erpm):
    rpm_motor = erpm / pole_pairs           # 电转速 → 电机机械转速
    rpm_wheel = rpm_motor / gear_ratio      # → 轮转速 (5.2:1 减速)
    rad_s = rpm_wheel * 2 * pi / 60        # → rad/s
    return rad_s * wheel_radius          # → m/s

# 差速模型 (四驱简化为双轮差速: 左侧平均, 右侧平均)
v_left  = (v_FL + v_RL) / 2
v_right = (v_FR + v_RR) / 2

v_robot = (v_right + v_left) / 2
w_robot = (v_right - v_left) / track_width
```

### 2.5 速度→电流映射

**实测数据 (来自 `candump`):**

| 场景 | CAN 电流值 | 实际电流 | 估算线速度 |
|------|:---:|------|------|
| 静止 | `0x0000` | 0A | 0 m/s |
| 慢速前进 | `0x0064` | +1.0A | ~0.15 m/s |
| 快速前进 | `0x01F4` | +5.0A | ~0.40 m/s |
| 后退 | `0xFF9C` | -1.0A | ~-0.15 m/s |

**简化映射 (待实车标定):**
```
current = clip(v_target / MAX_VELOCITY * MAX_CURRENT, -MAX_CURRENT, +MAX_CURRENT)
```
其中 `MAX_VELOCITY` 和 `MAX_CURRENT` 为可配置参数，定义在 `cleaning_robot_common/config.py`。

### 2.6 共享模块依赖

`chassis_driver` 的常量、运动学公式和 CAN 帧构造均从共享包 `cleaning_robot_common` 引用：

| 模块 | 内容 | chassis_driver 引用 |
|------|------|---------------------|
| `config.py` | CAN ID、电机参数、Topic 名称、安全限值 | `DRIVE_IDS`, `WHEEL_RADIUS_M`, `TOPIC_ODOM` 等 |
| `kinematics.py` | 差速分解、erpm→线速度、里程计积分 | `diff_decompose()`, `erpm_to_ms()`, `integrate_odom()` |
| `can_protocol.py` | CAN 帧构造/解析 | `make_current_frame()`, `make_query_frame()`, `parse_query_erpm()` |

所有节点统一从 `cleaning_robot_common.config` 导入参数，消除散落重复定义。

## 3. ROS2 接口

### 3.1 Node 信息

| 项目 | 内容 |
|------|------|
| ROS2 Node | `chassis_driver` |
| 语言 | Python 3.10+ |
| 依赖 | `python-can`, `rclpy`, `geometry_msgs`, `nav_msgs`, `tf2_ros` |

### 3.2 订阅

| Topic | 消息类型 | QoS | 说明 |
|-------|---------|-----|------|
| `/cmd_vel` | `geometry_msgs/msg/Twist` | Sensor Data, KeepLast(1) | 目标速度指令 (来自 master_bridge 或 master_controller) |

### 3.3 发布

| Topic | 消息类型 | 频率 | 说明 |
|-------|---------|------|------|
| `/odom` | `nav_msgs/msg/Odometry` | 50 Hz (与查询周期同步) | 里程计 |
| `/chassis/status` | `cleaning_robot_interfaces/msg/ChassisStatus` | 10 Hz | 电机状态 (电流/温度/故障码) |
| `tf` (odom→base_link) | `tf2_msgs/msg/TFMessage` | 50 Hz | 里程计 TF |

### 3.4 Service

| Service | 类型 | 说明 |
|---------|------|------|
| `chassis/emergency_stop` | `std_srvs/srv/Trigger` | 急停: 所有电机电流清零, 停止心跳 |

## 4. 功能需求

### 4.1 CAN 收发循环

**主循环 (20ms 周期):**

```
对于每个查询周期:
  1. 轮询 4 台行走电机转速 (CAN ID 001→003→002→004 交替)
     - 发送查询帧: [0x0F, 0x01]
     - 等待响应帧: DATA[2:6] = int32 erpm
  2. 将转速差速模型 → 线速度+角速度 → 积分更新里程计
  3. 发布 /odom + tf
  
对于每个心跳周期 (10ms):
  4. 对每台电机交替发送心跳帧 [0x00] 或电流帧 [0x01, hi, lo]
```

**CAN 帧编组:**
- 行走电机: 001/003 (左侧) 与 002/004 (右侧) 编组
- 左转时: 左侧电流 ≤ 0, 右侧电流 ≥ 0
- 右转时: 左侧电流 ≥ 0, 右侧电流 ≤ 0
- 刀盘电机 (005): 独立控制, 仅在 CLEAN 模式下启用 (二期)

### 4.2 cmd_vel → CAN 电流

```
输入: Twist.linear.x (m/s), Twist.angular.z (rad/s)

1. 差速分解:
   v_left  = linear.x - angular.z * track_width / 2
   v_right = linear.x + angular.z * track_width / 2

2. 速度 → 电流 (线性比例):
   i_left  = clamp(v_left  / max_velocity * max_current, -max_current, +max_current)
   i_right = clamp(v_right / max_velocity * max_current, -max_current, +max_current)

3. 分配到各轮:
   左前 (001) = 左后 (003) = i_left
   右前 (002) = 右后 (004) = i_right

4. CAN 帧:
   001: [0x01, hi(i_left), lo(i_left)]
   002: [0x01, hi(i_right), lo(i_right)]
   003: 同 001
   004: 同 002
```

### 4.3 里程计发布

```python
# 积分 (使用中值法)
theta += w_robot * dt
x += v_robot * cos(theta) * dt
y += v_robot * sin(theta) * dt

# 发布 nav_msgs/Odometry
odom_msg.pose.pose.position.x = x
odom_msg.pose.pose.position.y = y
odom_msg.pose.pose.orientation = quaternion_from_yaw(theta)
odom_msg.twist.twist.linear.x = v_robot
odom_msg.twist.twist.angular.z = w_robot

# 协方差: 暂设固定经验值 (待标定)
odom_msg.pose.covariance[0] = 0.01   # x 方差 0.01m²
odom_msg.pose.covariance[7] = 0.01   # y 方差
odom_msg.pose.covariance[35] = 0.001 # θ 方差 0.001rad²
```

### 4.4 模拟模式

当 `simulate:=true` 时:
- 不打开 `can0` 接口
- 根据 `/cmd_vel` 的积分生成虚拟里程计 (完美无噪声)
- 发布 `/chassis/status` 中所有电流=0, 温度=25°C
- 记录日志 `[SIM] chassis_driver running in simulated mode`

### 4.5 故障处理

| 故障 | 检测 | 响应 |
|------|------|------|
| CAN 接口无法打开 | `can0` 不存在或无权限 | 日志报错, 进入模拟模式 (如果 simulate=true) 或退出 |
| 电机查询超时 (>100ms) | 查询帧发送后无响应 | 跳过该电机本轮里程计更新, 连续 5 次超时发布故障告警 |
| 电机温度过高 (>80°C) | 查询码 0x07 响应值 | 降低该电机最大电流 50%, 发布 WARN 告警 |
| /cmd_vel 超时 (>500ms) | 无新 Twist 消息 | 所有电机电流清零 (安全停止) |

## 5. 配置参数

```yaml
chassis_driver:
  ros__parameters:
    # CAN
    can_interface: "can0"
    can_bitrate: 500000

    # 运动学
    pole_pairs: 10              # 20 极电机, 10 对极
    gear_ratio: 5.2              # 5.2:1 减速箱
    wheel_radius: 0.08
    track_width: 0.53

    # 控制
    max_velocity: 0.5            # 最大线速度 (m/s), 待实车标定
    max_current: 500             # 最大电流 (×10mA = 5.0A)
    current_deadzone: 10         # 电流死区 (×10mA), 低于此值视为 0
    query_interval_ms: 20        # 转速查询周期
    heartbeat_interval_ms: 10    # 心跳发送周期

    # 安全
    cmd_vel_timeout_ms: 500      # /cmd_vel 超时 → 急停
    query_timeout_ms: 100        # 查询响应超时
    motor_temp_warn_c: 80.0      # 电机温度告警
    motor_temp_cutoff_c: 100.0   # 电机温度切断

    # 模拟
    simulate: false              # true = 无 CAN 硬件时生成虚拟数据
```
