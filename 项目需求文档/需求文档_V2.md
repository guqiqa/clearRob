# 智能环卫机器人控制系统 — 需求文档 V2

> 版本：V2.1 — 确定 ROS2 技术路线  
> 更新：2026-06-12

---

## 1. 系统定位

设计一套**智能环卫机器人控制系统**，面向城市/园区/室内环卫场景，实现垃圾清扫的自动化与智能化。

系统按三个独立平台组织：

| 平台 | 定位 | 核心职责 |
|------|------|----------|
| **训练平台** | 视觉模型生产线 | 环卫场景数据加载、YOLO 模型配置、训练调度、垃圾检测模型产出 |
| **验证平台** | 模型质量关卡 | 垃圾检测评估、模型指标对比、误检漏检可视化、回归测试 |
| **使用平台** | 机器人运行系统 | 集成八大功能模块 + 三种控制方式，完成路径规划、自动巡航、垃圾清扫 |

三个平台之间仅通过**模型文件 + 配置文件**传递信息，无运行时依赖。

---

## 2. 控制输入

系统集成三种控制方式，互为备份，按场景切换：

| 控制方式 | 适用场景 | 交互形式 |
|----------|----------|----------|
| **遥控器** | 现场调试、紧急接管、特殊地形作业 | 物理遥控器，低延迟直连，2.4GHz/蓝牙 |
| **App 控制** | 日常任务下发、远程监控、清扫报告查看 | 移动端 App，WiFi/4G 连接，地图选点/划区 |
| **语音控制** | 现场临时指令、无屏操作、辅助驾驶 | 离线语音唤醒 + 指令识别（"开始清扫""暂停""返回充电"） |

优先级规则：遥控器 > App > 语音（物理接管权最高），App 和语音可并行。

## 3. 系统模块

系统分为**八大模块**，每个模块封装为一个 ROS2 Node，模块间通过 ROS2 Topic/Service/Action 通信，各自独立开发、独立测试。

### 3.0 统一接口规范（ROS2 基础）

所有模块遵循 ROS2 通信范式：

**Topic（发布/订阅 — 数据流）：**
```yaml
命名规范: {module}/{action}[/{detail}]
QoS: 默认 Sensor Data (Reliable, Volatile, KeepLast)
消息格式: ROS2 .msg 自定义消息
示例:
  - vision/detect/list          # 视觉检测列表
  - lidar/scan/pointcloud       # 预处理点云
  - localization/pose           # 机器人位姿
```

**Service（请求/响应 — 配置与查询）：**
```yaml
命名规范: {module}/get_{param} 或 {module}/set_{param}
QoS: 默认 Services (Reliable, Volatile)
消息格式: ROS2 .srv 自定义服务
示例:
  - cleaning/get_status         # 查询清扫状态
  - motion/set_max_speed        # 设置最大速度
```

**Action（长时任务 — 带进度与取消）：**
```yaml
命名规范: {module}/{task_name}
消息格式: ROS2 .action 自定义动作
示例:
  - planner/navigate_to_goal    # 导航至目标点（含进度反馈）
  - cleaning/execute_cleanup    # 执行清扫（可取消）
```

**配置：**
- 每个节点的参数通过 ROS2 Parameter（YAML 文件加载）注入，不硬编码
- 运行时可通过 `ros2 param` 动态调参

**健康监测：**
- 每个节点发布心跳 Topic（1Hz），携带节点状态 + 故障码
- 利用 ROS2 自带 Node Lifecycle 管理节点生命周期（Unconfigured → Inactive → Active → Finalized）

### 3.1 控制接入模块（新增）

| 项目 | 内容 |
|------|------|
| ROS2 Node | `control_gateway` |
| 定位 | 系统入口，三种控制方式的统一接入与归一化 |
| 功能 | 指令翻译（遥控信号/App指令/语音文本 → 统一指令）、优先级裁决、指令合法性校验 |
| 发布 Topic | `control/cmd/unified`（归一化指令），`control/cmd/estop`（可直达运动模块） |
| 订阅 Topic | —（接收硬件的底层驱动不在本模块范围内，通过设备抽象层输入） |
| 提供服务 | `control/set_priority`（运行时调整优先级规则） |
| 优先级 | 遥控器 > App > 语音，指令冲突时高优先级覆盖低优先级，App 和语音可并行 |

**指令集（归一化后）：**

| 指令码 | 含义 | 来源 |
|--------|------|------|
| `START` | 开始清扫 | 遥控/App/语音 |
| `PAUSE` | 暂停清扫 | 遥控/App/语音 |
| `RESUME` | 恢复清扫 | 遥控/App/语音 |
| `STOP` | 停止并待命 | 遥控/App/语音 |
| `RETURN` | 返回充电站 | 遥控/App/语音 |
| `MANUAL` | 手动操控模式 | 遥控/App |
| `SET_AREA` | 设定清扫区域 | App |
| `SET_MODE` | 设定巡航模式 | App/遥控 |
| `ESTOP` | 紧急停止 | 遥控（最高优先级，可直达运动模块） |

---

### 3.2 主控调度模块（新增）

| 项目 | 内容 |
|------|------|
| ROS2 Node | `master_controller` |
| 定位 | 系统大脑，任务调度、状态管理、自动巡航逻辑 |
| 功能 | 接收归一化指令 → 转化为任务调度 → 管理清扫生命周期；运行自动巡航状态机；系统异常处理与降级 |
| 订阅 Topic | `control/cmd/unified`（归一化指令）、`planner/status/state`（路径状态）、`motion/status/fault`、`cleaning/status/dust_full` |
| 发布 Topic | `master/task/area`、`master/task/mode`、`master/task/clean_strategy`、`master/cmd/motion_start` |
| 提供服务 | `master/get_lifecycle_state`（查询当前状态机状态） |
| 生命周期 | 遵循 ROS2 Lifecycle 管理，状态机内部自治 |

**自动巡航状态机：**

```
           ┌──────────┐
           │  待命中   │ ← 充电完成 / STOP 指令
           └────┬─────┘
        START↓
           ┌──────────┐
           │  路径规划  │ ← App 设定区域
           └────┬─────┘
        规划完成↓
           ┌──────────┐
      ┌───→│  巡逻巡航  │ ← 发现垃圾则进入清扫
      │    └────┬─────┘
      │ PAUSE↓  ↓RETURN/低电量/尘满
      │    ┌──────────┐     ┌──────────┐
      │    │  暂停    │     │  返航    │
      │    └────┬─────┘     └────┬─────┘
      │ RESUME↓              到达↓
      │    ┌──────────┐     ┌──────────┐
      │    │  定点清扫  │     │  充电中   │
      │    └────┬─────┘     └──────────┘
      │ 清扫完成↓
      └─── 回归巡逻 ──────────────┘
```

### 3.3 路径规划模块（新增）

| 项目 | 内容 |
|------|------|
| ROS2 Node | `path_planner` |
| 定位 | 接收清扫区域与地图，计算最优清扫路径 |
| 功能 | 全局覆盖路径（牛耕式 + 边界回形）、局部避障重规划、多区域清扫顺序优化 |
| 订阅 Topic | `localization/map/occupancy`（占据栅格地图）、`lidar/obstacle/list`（障碍物列表） |
| 发布 Topic | `planner/output/path`（目标路径点序列）、`planner/status/state` |
| Action Server | `planner/navigate_to_goal`（带进度的导航） |
| Action Client | 调用 `motion/follow_path`（下发给运动模块执行） |
| 算法 | 全局：Boustrophedon 分解 + TSP（多区域）；局部：DWA / TEB |

### 3.4 运动模块

| 项目 | 内容 |
|------|------|
| ROS2 Node | `motion_controller` |
| 定位 | 执行机构，响应运动指令 |
| 功能 | 底盘驱动、速度闭环控制、差速转向、急停、坡道辅助 |
| 订阅 Topic | `planner/output/path`（或 Action `motion/follow_path`）、`motion/cmd/velocity`、`motion/cmd/estop`（急停 — LiDAR 硬直达 + 遥控器） |
| 发布 Topic | `motion/odom`（里程计）、`motion/status/motor`、`motion/status/fault` |
| Action Server | `motion/follow_path`（执行路径跟踪） |
| 提供服务 | `motion/set_max_speed`、`motion/get_status` |
| 驱动方式 | 四驱电机 |
| 转向方式 | 差速转弯 |

### 3.5 定位模块

| 项目 | 内容 |
|------|------|
| ROS2 Node | `localization_engine` |
| 定位 | 感知自身位置与建图 |
| 功能 | 实时 SLAM、占据栅格地图构建与更新、全局/局部坐标系转换、tf2 坐标变换发布 |
| 订阅 Topic | `lidar/scan/pointcloud`（预处理点云）、`motion/odom`（里程计）、IMU Topic |
| 发布 Topic | `localization/pose`（位姿）、`localization/map/occupancy`（占据栅格地图）、`localization/confidence`、TF 坐标变换（tf2） |
| 提供服务 | `localization/get_current_pose`、`localization/request_map` |
| 关键能力 | 回环检测、动态环境适应、局部定位漂移修正 |

---

### 3.6 视觉识别模块

| 项目 | 内容 |
|------|------|
| ROS2 Node | `vision_detector` |
| 定位 | 视觉感知，垃圾检测与分类 |
| 功能 | 垃圾检测与分类、障碍物识别、可通行区域判断 |
| 模型 | YOLO 系列（YOLOv8→v10），目标检测 |
| 订阅 Topic | Camera 图像 Topic（`sensor/camera/image_raw`） |
| 发布 Topic | `vision/detect/list`（检测列表）、`vision/detect/cleanliness`（清洁度）、`vision/detect/drivable`（可通行区域） |
| 提供服务 | `vision/set_model`（热切换模型）、`vision/get_status` |
| 检测类别 | 可回收垃圾、厨余垃圾、有害垃圾、其他垃圾、落叶、烟头、大型障碍物、行人/宠物 |

> 视觉识别模块与训练平台/验证平台形成闭环：训练平台产出模型 → 验证平台评估模型 → 使用平台加载模型。模型文件通过 ROS2 Parameter 指定路径。

---

### 3.7 清扫模块

| 项目 | 内容 |
|------|------|
| ROS2 Node | `cleaning_actuator` |
| 定位 | 执行机构，执行清扫动作 |
| 功能 | 主刷/边刷控制、吸力调节、洒水量控制、尘满检测 |
| 订阅 Topic | `master/task/clean_strategy`（清扫策略指令）、`vision/detect/list`（垃圾信息）、`vision/detect/cleanliness`（清洁度） |
| 发布 Topic | `cleaning/status/progress`、`cleaning/status/dust_full`、`cleaning/status/brush`、`cleaning/stats/area`、`cleaning/stats/waste_volume` |
| Action Server | `cleaning/execute_cleanup`（可取消的清扫动作） |
| 提供服务 | `cleaning/get_status` |
| 清扫策略 | 覆盖式（全场清扫）、定点式（垃圾密集区）、追踪式（跟随垃圾路径） |
| 联动 | 视觉检测到垃圾 → 主控调度决策 → 清扫模块执行对应策略 → 视觉验证清洁度 → 决定是否重扫 |

---

### 3.8 激光雷达模块

| 项目 | 内容 |
|------|------|
| ROS2 Node | `lidar_perception` |
| 定位 | 环境感知，三维几何信息获取 |
| 功能 | 环境扫描、障碍物检测与测距、点云预处理（滤波/去畸变/聚类）、后融合 |
| 订阅 Topic | LiDAR 原始数据 Topic（`sensor/lidar/scan_raw`）、`vision/detect/list`（视觉检测结果，用于后融合） |
| 发布 Topic | `lidar/scan/pointcloud`（预处理点云）、`lidar/obstacle/list`（障碍物列表+3D位置）、`lidar/fusion/3d_target`（后融合 3D 目标信息）、`lidar/cmd/estop` |
| 提供服务 | `lidar/get_status`、`lidar/set_scan_freq` |
| 生命周期 | 遵循 ROS2 Lifecycle；视觉检测 Topic 超时时降级为纯 LiDAR 模式（无融合输出） |
| 与定位模块协作 | 发布预处理点云至 `lidar/scan/pointcloud`，定位模块订阅后建图 |
| 与运动模块协作 | **硬直达通道**：`lidar/cmd/estop` Topic 直连运动模块 `motion/cmd/estop`，不经过主控链路 |
| 与视觉模块融合 | **后融合方式**：雷达模块订阅 `vision/detect/list` → 将 2D 检测框映射到点云进行空间关联 → 发布 `lidar/fusion/3d_target` 上报告警，主控调度订阅判断是否需要紧急处理 |

### 4.2 消息主题总览（ROS2 通信清单）

```text
# ===== 控制流 (control_gateway → master_controller) =====
control/cmd/unified          # Topic: 归一化指令 (CleaningCommand.msg)
control/cmd/estop            # Topic: 紧急停止，可直达 motion_controller

# ===== 主控调度流 (master_controller → 各模块) =====
master/task/area             # Topic: 清扫区域任务
master/task/mode             # Topic: 模式切换 (CRUISE/CLEAN/RETURN)
master/task/clean_strategy   # Topic: 清扫策略选择
master/cmd/motion_start      # Topic: 运动启停

# ===== 路径规划流 (path_planner) =====
planner/input/map             # 订阅: localization/map/occupancy
planner/input/obstacles       # 订阅: lidar/obstacle/list
planner/output/path           # Topic: 发布目标路径点序列 (Path.msg)
planner/status/state          # Topic: 路径执行状态
planner/navigate_to_goal      # Action: 导航至目标点（带进度反馈）

# ===== 运动流 (motion_controller) =====
motion/odom                   # Topic: 里程计 (Odometry.msg)
motion/status/motor           # Topic: 电机状态
motion/status/fault           # Topic: 故障码
motion/cmd/velocity           # Topic: 速度/角速度指令 (Twist.msg)
motion/cmd/estop              # Topic: 急停订阅（来自 lidar + control）
motion/follow_path            # Action: 路径跟踪执行
motion/set_max_speed          # Service: 设置最大速度
motion/get_status             # Service: 查询运动状态

# ===== 定位流 (localization_engine) =====
localization/pose             # Topic: 机器人位姿 (PoseWithCovariance.msg)
localization/map/occupancy    # Topic: 占据栅格地图 (OccupancyGrid.msg)
localization/confidence       # Topic: 定位置信度
localization/status           # Topic: 定位状态
localization/get_current_pose # Service: 查询当前位姿
localization/request_map      # Service: 请求地图数据
tf                           # tf2: 坐标变换广播

# ===== 视觉流 (vision_detector) =====
vision/detect/list            # Topic: 检测列表 (DetectionArray.msg)
vision/detect/cleanliness     # Topic: 清洁度评分
vision/detect/drivable        # Topic: 可通行区域
vision/status                 # Topic: 视觉模块状态
vision/set_model              # Service: 热切换模型
vision/get_status             # Service: 查询视觉状态

# ===== 清扫流 (cleaning_actuator) =====
cleaning/cmd/execute          # Topic: 清扫执行指令
cleaning/status/progress      # Topic: 清扫进度
cleaning/status/dust_full     # Topic: 尘满告警
cleaning/status/brush         # Topic: 刷盘状态
cleaning/stats/area           # Topic: 已清扫面积
cleaning/stats/waste_volume   # Topic: 预估垃圾量
cleaning/execute_cleanup      # Action: 执行清扫（可取消）
cleaning/get_status           # Service: 查询清扫状态

# ===== 激光雷达流 (lidar_perception) =====
lidar/scan/pointcloud         # Topic: 预处理后点云 (PointCloud2.msg)
lidar/obstacle/list           # Topic: 障碍物列表与3D位置
lidar/fusion/3d_target        # Topic: 后融合 3D 目标信息
lidar/cmd/estop               # Topic: 硬直达急停信号
lidar/status                  # Topic: 雷达状态
lidar/get_status              # Service: 查询雷达状态
lidar/set_scan_freq           # Service: 设置扫描频率

# ===== 传感器原始数据 =====
sensor/camera/image_raw       # Topic: Camera RGB 图像 (Image.msg)
sensor/lidar/scan_raw         # Topic: LiDAR 原始扫描 (LaserScan.msg)
sensor/imu/data               # Topic: IMU 数据 (Imu.msg)

# ===== 系统流 =====
system/heartbeat/{node_name}  # Topic: 各节点心跳 (1Hz, Heartbeat.msg)
system/alert                  # Topic: 系统告警 (Alert.msg)
```

```
                          ┌─────────────▼─────────────┐
                          │     lidar_perception       │
                          │ 点云预处理/障碍物检测/后融合  │
                          │ 急停判断 → 硬直达           │
                          └─────────────┬─────────────┘
                                        │ lidar/scan/pointcloud
                          ┌─────────────▼─────────────┐
                          │   localization_engine     │
                          │ SLAM / 建图 / 位姿估算     │
                          │ tf2 广播 / 回环检测        │
                          └───────────────────────────┘

ROS2 通信标注:
  ────→  Topic (发布/订阅) — 默认 QoS: Sensor Data
  ═════→ 硬直达 Topic (不经过 master_controller)
  - - -→ 后融合数据流 (vision_detector → lidar_perception)
  Action:  长时任务 (如 navigate_to_goal, follow_path)
  Service: 请求/响应 (如 set_model, get_status)
  tf2:     坐标变换广播 (localization_engine → 全局)
```

## 6. 架构原则

- **模块独立**：八大模块各自封装为 ROS2 Node，独立开发、独立测试，通过 Topic/Service/Action 解耦通信
- **平台分离**：训练/验证/使用三个平台无运行时依赖，仅共享模型文件和配置
- **配置驱动**：模型结构、清扫策略、控制参数均通过 ROS2 Parameter（YAML）控制，支持 `ros2 param` 运行时调参
- **生命周期管理**：各节点使用 ROS2 Lifecycle 管理，从 Unconfigured → Inactive → Active，支持优雅启停
- **可扩展**：新增传感器、控制方式、功能模块，增加 ROS2 Node 即可，无需修改现有节点

### 6.1 模块完整性检查

对系统所有功能进行遍历，确认无归属盲区：

| 功能/需求 | 负责模块 | 状态 |

## 7. 方案选型论证：纯 LiDAR 避障 vs Camera+LiDAR 混合

### 7.1 环卫场景的特殊性

与自动驾驶不同，环卫机器人面临的挑战：
- 需要**分类垃圾**（可回收/不可回收/有害），纯几何信息无法区分
- 需要判断**清洁度**（地面是否干净），这是视觉任务
- 低速运行（≤1.5m/s），对远距离感知要求低，对近距离语义要求高
- 场景包括室内（走廊/大厅）和半室外（园区/人行道），GPS 不可靠

### 7.2 关键场景对比

| 场景 | 纯 LiDAR | Camera + LiDAR |
|------|----------|----------------|
| 区分烟头 vs 地砖缝隙 | 无法区分 | YOLO 视觉识别 |
| 湿垃圾 vs 水渍 | 形状均不规则 | 颜色/纹理区分 |
| 玻璃门前避障 | 激光透射，可能漏检 | Camera 识别门框/玻璃 |
| 黑色地面/地毯 | LiDAR 吸收激光，数据缺失 | Camera 不受影响 |
| 强光/逆光 | 不受影响 | Camera 短暂致盲，LiDAR 接管 |
| 夜间户外清扫 | LiDAR 可避障但无法分类垃圾 | Camera 红外模式辅助 |

### 7.3 结论

混合方案为项目基础路线。环卫场景对垃圾**分类**和**清洁度判断**是刚性需求——纯 LiDAR 无法满足。Camera 负责"这是什么垃圾"，LiDAR 负责"它在什么位置、距离多远"。
