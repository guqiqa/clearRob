> 版本：V3.1 — 电机参数修正(20极/10对极+5.2:1减速比) + 一期程序模块化拆分(cleaning_robot_common)

> 总纲：需求文档_自主控制系统_V1.3.md（硬件现状 + CAN 协议 + 三期架构 + 电机修正 + 模块化）

## 1. 系统定位

设计一套**智能环卫机器人控制系统**，部署于移远 Quectel QSM602HA-GL 开发板（D-Robotics X5 SoC, ARM64, 4GB RAM），通过 CAN 总线直驱 OID FOC 无刷电机，实现从遥控行驶 → 自主导航避障 → 全自主智能作业的三期演进。

### 1.1 与 V2.x 通用版的关系

V2.x 需求文档（`需求文档_V2.5.md` 及 10 份模块细化文档）为**通用架构设计**，假设 x86 Ubuntu + LiDAR + ONNX Runtime。本 V3.0 为**实际落地版本**，以 V2.x 的模块化设计理念为基础，适配真实硬件平台。

差异汇总：

| 维度 | V2.x (通用设计) | V3.0 (落地版) |
|------|----------------|--------------|
| 目标平台 | x86 Ubuntu 22.04 | ARM64 QSM602HA-GL (X5 SoC) |
| 避障方案 | 2D LiDAR + 视觉融合 | 毫米波雷达 + 视觉融合 (二期) |
| 定位 | LiDAR SLAM (slam_toolbox) | 轮式里程计 + IMU + RTK 融合 |
| AI 推理 | ONNX Runtime CPU/GPU | BPU libdnn.so + .hbm 模型 |
| 底盘控制 | 抽象 motion_controller (ROS2 Twist) | CAN 500Kbps 直驱 OID FOC 电机 ×5 |
| 控制输入 | 遥控器/App/语音 | 一期仅遥控器 (SBUS 16ch) |
| 操作系统 | Ubuntu 22.04 + ROS2 Humble | 同 (设备已有 Ubuntu + ROS2) |
| 模块数量 | 9 个 | 7 个 (一期) → 8 个 (二期) |

## 3. 三期架构

```
第一期 (现在)         第二期 (感知)           第三期 (全自主)
─────────────────    ─────────────────    ─────────────────
CAN 直驱底盘          + 毫米波雷达          + 区域调度
IMU + RTK + 里程计    + BPU 视觉推理       + 自动回充
遥控器 (SBUS)         + 雷达+视觉融合       + 增量建图
ROS2 数据链路          + 垃圾识别分类        + MQTT 远程监控
                      + 全覆盖路径规划
                      + 自主避障绕行
```

本 V3.0 文档覆盖第一期和第二期。

### 4.0.1 共享模块 (cleaning_robot_common)

**定位**：非 ROS Node，是纯 Python 库包。所有一期节点通过 `from cleaning_robot_common.xxx import ...` 引用。

| 子模块 | 文件 | 内容 | 引用者 |
|--------|------|------|--------|
| **config** | `config.py` | CAN ID (001-005)、电机参数(10对极/5.2:1/0.08m)、Topic 名称(`/cmd_vel`等)、SBUS 协议常量、IMU 校准系数、安全限值 | 全部节点 |
| **kinematics** | `kinematics.py` | 差速分解 `diff_decompose()`, erpm→线速度 `erpm_to_ms()`, 速度→CAN电流 `ms_to_current()`, 里程计积分 `integrate_odom()`, 四元数转换 `yaw_to_quaternion()` | chassis_driver |
| **can_protocol** | `can_protocol.py` | CAN 帧构造 `make_current_frame()`/`make_heartbeat_frame()`/`make_query_frame()`, 响应解析 `parse_query_erpm()` | chassis_driver |

**设计原则**：
- 所有函数为无状态纯函数，可独立单元测试
- 各节点可通过 ROS2 Parameter 覆盖 config 中的默认值
- 修改电机参数只需改 config.py 一处，全项目同步

### 4.1 底盘驱动模块

| 项目 | 内容 |
|------|------|
| ROS2 Node | `chassis_driver` |
| 定位 | CAN 总线直驱 OID FOC 电机，轮速查询 → 里程计 |
| 订阅 Topic | `/cmd_vel` (geometry_msgs/Twist) |
| 发布 Topic | `/odom` (nav_msgs/Odometry)、`/chassis/status` (自定义电机状态) |
| 硬件接口 | `can0` (SocketCAN, 500 Kbps) |
| 控制协议 | CAN ID 001-004: int16 电流值 (10mA/unit)；CAN ID 005: 刀盘电机；心跳帧 0x00 交替发送；查询帧 0x0F 读取转速 (erpm) |
| 里程计 | 差速模型: erpm→rpm→线速度, 积分 → odom |

### 4.2 IMU 驱动模块

| 项目 | 内容 |
|------|------|
| ROS2 Node | `imu_driver` |
| 定位 | QMI8658 6 轴 IMU 数据采集 |
| 发布 Topic | `/imu/data` (sensor_msgs/Imu) |
| 硬件接口 | `/dev/qmi8658_imu`, 阻塞读取 24 字节 struct |
| 校准 | 手册提供的 6 参数校准系数 |

### 4.3 RTK 驱动模块

| 项目 | 内容 |
|------|------|
| ROS2 Node | `rtk_driver` |
| 定位 | NTRIP 高精度 GNSS 定位 |
| 发布 Topic | `/fix` (sensor_msgs/NavSatFix) |
| 硬件接口 | `/dev/ttyS2` @ 460800bps, NMEA 0183 |

### 4.4 遥控器驱动模块

| 项目 | 内容 |
|------|------|
| ROS2 Node | `remote_driver` |
| 定位 | SBUS 遥控器信号解析 |
| 发布 Topic | `/joy` (sensor_msgs/Joy) |
| 硬件接口 | `/dev/ttyS1` @ 115200bps (经 MCU), SBUS 16ch |

### 4.5 主控桥接模块 (一期)

| 项目 | 内容 |
|------|------|
| ROS2 Node | `master_bridge` |
| 定位 | 一期状态机 + 遥控→底盘桥接 |
| 状态机 | STANDBY ↔ MANUAL (遥控器 START/STOP 切换) |
| 订阅 Topic | `/joy` (sensor_msgs/Joy) |
| 发布 Topic | `/cmd_vel` (geometry_msgs/Twist)、`/system/heartbeat/master_bridge` |

### 4.6 视觉检测模块 (二期)

| 项目 | 内容 |
|------|------|
| ROS2 Node | `vision_detector` |
| 定位 | BPU YOLO 目标检测：垃圾 8 类 |
| 推理后端 | Horizon BPU (`libdnn.so`), `.hbm` 模型 (由 ONNX → HBCC 编译) |
| 订阅 Topic | `sensor/camera/image_raw`、`master/task/mode` |
| 发布 Topic | `vision/detect/list` (DetectionArray)、`vision/detect/cleanliness`、`vision/status` |
| 类别 | recyclable(0), kitchen_waste(1), hazardous(2), other_waste(3), green_waste(4), pedestrian(5), obstacle(6), stain(7) |

### 4.7 毫米波雷达模块 (二期)

| 项目 | 内容 |
|------|------|
| ROS2 Node | `radar_driver` |
| 定位 | 毫米波雷达目标检测与追踪（全天候避障） |
| 输出 | 距离 + 方位角 + 径向速度 (多普勒) |
| 局限 | 2D 雷达，无俯仰角/高度信息，需摄像头补偿 |

### 4.8 融合引擎模块 (二期)

| 项目 | 内容 |
|------|------|
| ROS2 Node | `fusion_engine` |
| 定位 | 雷达+视觉后融合 → 避障决策 |
| 输入 | `vision/detect/list` + `radar/obstacles` |
| 输出 | `fusion/obstacle/decision` → path_planner |
| 物理隔离 | vision_detector 不直接向 path_planner 发布 Topic |
| 深度增强 | 摄像头检测框 + 深度采样 (depth_m) → 补偿雷达缺失的高度信息 |

### 4.9 路径规划模块 (二期)

| 项目 | 内容 |
|------|------|
| ROS2 Node | `path_planner` |
| 定位 | 覆盖路径规划 (弓字形) + 道路清扫 + 局部避障 |
| 定位依赖 | `/odom` + `/imu/data` + `/fix` (替代 LiDAR SLAM) |
| 保留 | boustrophedon 覆盖算法、Pure Pursuit 轨迹跟踪 |
| 避障 | 订阅 `fusion/obstacle/decision` |

### 4.10 主控调度模块 (二期)

| 项目 | 内容 |
|------|------|
| ROS2 Node | `master_controller` |
| 定位 | 全模式状态机 + 任务调度 |
| 状态 | STANDBY / MANUAL / CRUISING / CLEANING / RETURNING |
| 复用 | 参考工程 `master_node.py` 状态机 + 发令枪模式 |

### 4.11 清扫模块 (二期)

| 项目 | 内容 |
|------|------|
| ROS2 Node | `cleaning_actuator` |
| 定位 | 刀盘电机 CAN ID=005 控制 + 清洁度反馈 |

## 6. 消息主题总览

```text
# ===== 一期: 驱动层 =====
/joy                          # remote_driver → sensor_msgs/Joy
/cmd_vel                      # master_bridge → chassis_driver (geometry_msgs/Twist)
/odom                         # chassis_driver → nav_msgs/Odometry
/imu/data                     # imu_driver → sensor_msgs/Imu
/fix                          # rtk_driver → sensor_msgs/NavSatFix
/chassis/status               # chassis_driver → 自定义 ChassisStatus

# ===== 二期: 感知与决策 =====
vision/detect/list            # vision_detector → DetectionArray (含 depth_m)
vision/detect/cleanliness     # vision_detector → Float32
vision/status                 # vision_detector → VisionStatus
radar/obstacles               # radar_driver → 自定义 RadarObstacleList
fusion/obstacle/decision      # fusion_engine → FusionDecision → path_planner
fusion/3d_target              # fusion_engine → Fusion3DTarget → master_controller

# ===== 二期: 调度与控制 =====
master/task/mode              # master_controller → TaskMode
master/task/area              # master_controller → path_planner (TaskArea)
planner/output/path           # path_planner → Path → master_controller
planner/status/state          # path_planner → PlannerState
cleaning/cmd/execute          # master_controller → cleaning_actuator

# ===== 系统 =====
system/heartbeat/{node_name}  # 各节点 → Heartbeat (1Hz)
system/alert                  # 各节点 → Alert
```

## 7. 部署规范

### 7.1 ROS2 安装 (ARM64)

```bash
sudo apt update
sudo apt install ros-humble-ros-base
# 二期增加: ros-humble-navigation2 ros-humble-nav2-bringup
```

### 7.2 编译

```bash
cd cleaning_robot_ws
# ARM64 4GB 环境: 必须单线程编译防止 OOM
colcon build --executor sequential --symlink-install
```

### 7.3 设备权限

```bash
# 每次启动前
sudo ip link set can0 type can bitrate 500000
sudo ip link set up can0
sudo chmod 666 /dev/ttyS* /dev/qmi8658_imu
```

### 7.4 一期启动

```bash
ros2 launch cleaning_robot_bringup phase1_chassis.launch.py
```

## 8. 架构原则

- **不依赖厂商闭源程序**：每个硬件设备从底层驱动，协议公开可验证
- **模块独立**：每个驱动/功能节点为独立 ROS2 Node，可单独启停、调试
- **共享模块管理**：`cleaning_robot_common` 包统一管理全局常量、运动学公式和 CAN 帧协议——所有节点引入同一份配置，消除散落重复定义；纯函数设计支持独立单元测试
- **分布式调试**：设备跑计算，PC 跑 RViz2 显示
- **分期交付**：每期有可运行、可演示的产出
- **配置驱动**：所有参数通过 ROS2 Parameter (YAML) 注入，可覆盖 common 模块默认值
- **模拟兼容**：每个驱动节点支持 `simulate:=true` 参数，在无硬件环境下生成虚拟数据
- **物理隔离** (继承 V2.x)：vision_detector 不直接向 path_planner 发布 Topic

## 9. 与 V2.x 的兼容性

- `Detection.msg` / `DetectionArray.msg` 消息格式保持与 V2.x 兼容
- vision_detector 的 8 类检测体系和模式感知策略继承 V2.x 设计
- V2.x 中直接可复用的内容：YOLO 训练管线、cleanliness 评分算法、mode-aware filtering、boustrophedon 覆盖算法
- V2.x 中不适用于本平台的内容：LiDAR SLAM 定位、ONNX Runtime 推理、lidar_perception 模块、motion_controller 模块
