## 1. 系统定位

设计一套**智能环卫机器人控制系统**，部署于移远 Quectel QSM602HA-GL 开发板（D-Robotics X5 SoC, ARM64, 4GB RAM），通过 CAN 总线直驱 OID FOC 无刷电机，实现从遥控行驶 → 自主导航避障 → 全自主智能作业的三期演进。

### 1.1 与 V2.x 通用版的关系

V2.x 需求文档（`需求文档_V2.5.md` 及 10 份模块细化文档）为**通用架构设计**，假设 x86 Ubuntu + LiDAR + ONNX Runtime。本 V3.0 为**实际落地版本**，以 V2.x 的模块化设计理念为基础，适配真实硬件平台。

差异汇总：

| 维度 | V2.x (通用设计) | V3.0 (落地版) |
|------|----------------|--------------|
| 目标平台 | x86 Ubuntu 22.04 | ARM64 QSM602HA-GL (X5 SoC) |
| 避障方案 | 2D LiDAR + 视觉融合 | 毫米波雷达 + 视觉融合 (二期) |
| 定位 | LiDAR SLAM (slam_toolbox) | 轮式里程计 + IMU + RTK 融合 |
| AI 推理 | ONNX Runtime CPU/GPU | BPU libdnn.so + .hbm 模型 |
| 底盘控制 | 抽象 motion_controller (ROS2 Twist) | CAN 500Kbps 直驱 OID FOC 电机 ×5 |
| 控制输入 | 遥控器/App/语音 | 一期仅遥控器 (SBUS 16ch) |
| 操作系统 | Ubuntu 22.04 + ROS2 Humble | 同 (设备已有 Ubuntu + ROS2) |
| 模块数量 | 9 个 | 7 个 (一期) → 8 个 (二期) |

### 2.3 CAN 总线通信协议（OID FOC，已实测解析）

#### 物理层

| 参数 | 值 |
|------|------|
| 接口 | `can0` (SocketCAN) |
| 波特率 | 500 Kbps |
| 帧类型 | 标准数据帧 (11-bit ID) |
| **字节序** | 多字节负载 **大端 (Big-endian)**（实测确认） |

#### 电机 CAN ID

| CAN ID | 电机 | 功能 |
|:---:|------|------|
| `001` | 左后轮 | 行走驱动 |
| `002` | 左前轮 | 行走驱动 |
| `003` | 右后轮 | 行走驱动 |
| `004` | 右前轮 | 行走驱动 |
| `005` | 刀盘 | 切割/清扫 (二期) |

驱动轮顺序：`[1, 2, 3, 4]`；左轮 `[2, 1]`（左前, 左后）；右轮 `[4, 3]`（右前, 右后）。

#### 指令帧（cmd 字节 = DATA[0]）

| 指令 | 字节0 | DLC | 负载 | 字节序 |
|------|:---:|:---:|------|:---:|
| **心跳** (keep-alive) | `0x00` | 1 | 无 | — |
| **电流控制** | `0x01` | 3 | `[cmd, int16 电流]` | 大端 |
| **速度控制** (驱动闭环) | `0x02` | 5 | `[cmd, int32 erpm]` | 大端 |
| **设置加速斜坡** | `0x0A` | 5 | `[cmd, int32 erpm/s]` | 大端 |
| **设置减速斜坡** | `0x10` | 5 | `[cmd, int32 erpm/s]` | 大端 |
| **设置闭环限流** | `0x14` | 3 | `[cmd, uint16 电流]` | 大端 |
| **查询** | `0x0F` | 2 | `[0x0F, 查询码]` | — |

> **重要实测**：本机驱动固件**不响应 0x02 速度命令**（总线实测确认），仅支持 `0x01` 电流模式。`wheel_control_mode = "current"` 为强制要求。

**电流缩放**：1 单位 = 10mA（`CURRENT_UNIT_MA = 10`）。电流控制钳位 int16 有符号 `[-32768, 32767]` 单位（= ±327.68A）；限流 uint16 钳位 `[0, 32767]`。

#### 查询码（byte1）

| 查询码 | 值 | 含义 |
|:---:|:---:|------|
| 故障 | `0x00` | 故障信息 |
| **转速** | `0x01` | 电机转速 (erpm, int32) |
| 电流 | `0x05` | 电机电流 (10mA 单位) |
| 温度 | `0x07` | 温度 (°C) |

#### 查询响应布局

- 最小响应 DLC：**6 字节**
- `DATA[0]` 必须 == `0x0F`（指令回显）
- ERPM 在 `DATA[2:6]`，**int32 大端**
- 通用 int16 解析（温度/电流响应）：`DATA[2:4]` **小端** int16

> 大端 ERPM 已对照厂商 WheelPID V2 程序确认；旧小端读取产生乱值。

#### CAN 时序

| 项 | 值 |
|------|:---:|
| 转速查询周期 | 20 ms |
| 心跳周期 | 40 ms（原 10ms 对 500kbps 太快） |
| 查询响应超时 | 100 ms |
| 底盘核心心跳 | 200 ms |
| 底盘核心查询 | 50 ms |

### 2.5 SBUS 遥控协议（C7mini 8通道）

#### 串口链路（两条路径）

| 路径 | 设备 | 波特率 | 模式 | 说明 |
|------|------|:---:|------|------|
| 直连（绕过 MCU） | `/dev/ttyS7` | 100000 | 8E2 标准 SBUS | C7mini 接收机→反相器→ttyS7 |
| MCU 回退（port_bridge） | `/dev/ttyS1` | 115200→100000 | 8N1→SBUS 透传 | remote_driver 实际使用 |

#### SBUS 帧格式

- 帧长 **25 字节**；头 byte0 = `0x0F`；尾 byte23 = `0x00`
- 通道 **16 × 11 bit**，LSB 优先打包
- 标志字节 `buf[23]`：bit0=CH17, bit1=CH18, bit2=frame_lost, bit3=failsafe

#### 值范围/重映射

- C7mini 原生 1000-2000，中心 1500
- port_bridge 重映射到标准 SBUS 范围：**min 172, 中心 992, max 1811**
- 校准：100 采样/通道中心，初始中心 992.0
- 同步：逐字节同步 `0x0F`，收 25 字节；CH[0]/CH[1] 在 100..2000 才接受

#### C7mini 通道映射

| 通道(1-based) | 功能 |
|:---:|------|
| CH1 | 右摇杆 L/R → 转向 |
| CH2 | 右摇杆 F/B（未用于控制） |
| CH3 | 左摇杆 F/B → 油门（左手油门） |
| CH4 | 左摇杆 L/R |
| CH5 | (未用为轴) |
| CH6 | SWA 三档（START/STOP） |
| CH7 | SWB 两档（ESTOP） |
| CH8/CH9 | VR1/VR2 旋钮 |

软件零基通道（config.py）：`RC_CH_STEERING=0`(CH1), `RC_CH_THROTTLE=2`(CH3), `RC_CH_SWA=5`(CH6), `RC_CH_SWB=6`(CH7)。

**按钮逻辑**：SWA 三档 200=上(ON)/1000=中(OFF)/1800=下(ON)，`btn_start = 1 if ch<700`；SWB 两档 1000/200，`btn_estop = 1 if (ch<700 or ch>1400)`。

### 2.6 IMU（QMI8658 六轴）

| 项 | 值 |
|------|------|
| 设备 | `/dev/qmi8658_imu`（O_RDONLY 阻塞读） |
| 发布频率 | 200 Hz |
| frame_id | `imu_link` |
| 原始帧 | `<iiiiii` 6×int32 **小端**，24 字节：(ax,ay,az,gx,gy,gz) |
| 原始缩放 | 1e6 LSB/m/s² 和 rad/s（值 = raw/1e6） |

**校准系数**（厂商 QMI8658 手册）：

| 系数 | 值 | 应用 |
|------|:---:|------|
| ax_offset | +0.320 | `ax = ax_raw/1e6 + 0.320` |
| ay_offset | +0.027 | `ay = ay_raw/1e6 + 0.027` |
| az_offset | +0.802 | `az = (az_raw/1e6 + 0.802) × 0.991` |
| az_scale | 0.991 | z 偏移后乘 |
| gx_offset | +0.0265 | `gx = gx_raw/1e6 + 0.0265` |
| gy_offset | -0.0135 | `gy = gy_raw/1e6 − 0.0135` |
| gz_offset | +0.0132 | `gz = gz_raw/1e6 + 0.0132` |

消息：`sensor_msgs/Imu` 于 `/imu/data`。不提供方向 → `orientation_covariance[0] = -1.0`。

### 2.7 RTK GNSS（NTRIP 高精度）

| 项 | 值 |
|------|------|
| 设备 | `/dev/ttyS2` |
| 波特率 | 460800 |
| frame_id | `gps_link` |
| 协议 | NMEA 0183（`$GPGGA` ≥15 字段、`$GPRMC` ≥10 字段 + 状态 'A'，XOR 校验） |
| 坐标转换 | ddmm.mmmm → 十进制度（N/S 取 2 位、E/W 取 3 位；S/W 负） |
| 消息 | `sensor_msgs/NavSatFix` 于 `/fix` |

**定位精度协方差**：RTK 固定(≥4)→0.01(1cm)；DGPS(≥2)→1.0(1m)；自主→25.0(5m)。高度协方差 = 协方差×4.0。

模拟：`sim_lat=31.2304`, `sim_lon=121.4737`, 高度 10.0, quality 4, 1Hz。

## 3. 三期架构

```
第一期 (现在)         第二期 (感知)           第三期 (全自主)
─────────────────    ─────────────────    ─────────────────
CAN 直驱底盘          + 毫米波雷达          + 区域调度
IMU + RTK + 里程计    + BPU 视觉推理       + 自动回充
遥控器 (SBUS)         + 雷达+视觉融合       + 增量建图
ROS2 数据链路          + 垃圾识别分类        + MQTT 远程监控
                      + 全覆盖路径规划
                      + 自主避障绕行
```

本 V3.0 文档覆盖第一期和第二期。

|--------|------|------|--------|
| **config** | `config.py` | CAN ID (001-005)、电机参数(10对极/5.2:1/0.08m)、Topic 名称(`/cmd_vel`等)、SBUS 协议常量、IMU 校准系数、安全限值 | 全部节点 |
| **kinematics** | `kinematics.py` | 差速分解 `diff_decompose()`, erpm→线速度 `erpm_to_ms()`, 速度→CAN电流 `ms_to_current()`, 里程计积分 `integrate_odom()`, 四元数转换 `yaw_to_quaternion()` | chassis_driver |
| **can_protocol** | `can_protocol.py` | CAN 帧构造 `make_current_frame()`/`make_heartbeat_frame()`/`make_query_frame()`, 响应解析 `parse_query_erpm()` | chassis_driver |

**设计原则**：
- 所有函数为无状态纯函数，可独立单元测试
- 各节点可通过 ROS2 Parameter 覆盖 config 中的默认值
- 修改电机参数只需改 config.py 一处，全项目同步

### 4.1 底盘驱动模块

| 项目 | 内容 |
|------|------|
| ROS2 Node | `chassis_driver`（Python 壳）+ `chassis_core`（C++ 核心 .so） |
| 定位 | CAN 总线直驱 OID FOC 电机，**控制逻辑嵌入同事实车调试的 C++ WheelPID V2 程序** |
| 控制逻辑 | 转向模型（内轮约束+弧线过渡）、原地旋转（5A 工厂电流）、IMU 航向保持、换向保持、LOW/MID/HIGH 档位、current 模式软件 PI 轮速环 |

## 8. 架构原则

- **不依赖厂商闭源程序**：每个硬件设备从底层驱动，协议公开可验证
- **模块独立**：每个驱动/功能节点为独立 ROS2 Node，可单独启停、调试
- **共享模块管理**：`cleaning_robot_common` 包统一管理全局常量、运动学公式和 CAN 帧协议——所有节点引入同一份配置，消除散落重复定义；纯函数设计支持独立单元测试
- **控制逻辑隔离**：底盘控制算法（同事实调 C++ WheelPID V2）编译为 `chassis_core` .so 独立于 ROS2，Python 壳只做 I/O 与仲裁——实调成果逐字节保留，且 I/O 层可自由替换
- **意图接口**：所有操控源统一通过 `/chassis/intent` 表达意图（throttle/steering/gear/estop），底盘按优先级仲裁——遥控、App、自主导航可插拔
- **分布式调试**：设备跑计算，PC 跑 RViz2 显示
- **分期交付**：每期有可运行、可演示的产出
- **配置驱动**：所有参数通过 ROS2 Parameter (YAML) 注入，可覆盖 common 模块默认值
- **模拟兼容**：每个驱动节点支持 `simulate:=true` 参数，在无硬件环境下生成虚拟数据
- **物理隔离** (继承 V2.x)：vision_detector 不直接向 path_planner 发布 Topic
