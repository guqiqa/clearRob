# 智能环卫机器人控制系统 — 需求文档 V2

> 版本：V2.3 — 重构运动指令链路（path_planner→master→motion），新增 localization/pose 实时位姿订阅
> 更新：2026-06-15

---

## 1. 系统定位

设计一套**智能环卫机器人控制系统**，面向城市/园区/室内环卫场景，实现垃圾清扫的自动化与智能化。

系统按三个独立平台组织：

| 平台 | 定位 | 核心职责 |
|------|------|----------|
| **训练平台** | 视觉模型生产线 | 环卫场景数据加载、YOLO 模型配置、训练调度、垃圾检测模型产出 |
| **验证平台** | 模型质量关卡 | 垃圾检测评估、模型指标对比、误检漏检可视化、回归测试 |
| **使用平台** | 机器人运行系统 | 集成八大功能模块 + 三种控制方式，完成路径规划、自动巡航、垃圾清扫 |

三个平台之间仅通过**模型文件 + 配置文件**传递信息，无运行时依赖。

---

## 2. 控制输入

系统集成三种控制方式，互为备份，按场景切换：

| 控制方式 | 适用场景 | 交互形式 |
|----------|----------|----------|
| **遥控器** | 现场调试、紧急接管、特殊地形作业 | 物理遥控器，低延迟直连，2.4GHz/蓝牙 |
| **App 控制** | 日常任务下发、远程监控、清扫报告查看 | 移动端 App，WiFi/4G 连接，地图选点/划区 |
| **语音控制** | 现场临时指令、无屏操作、辅助驾驶 | 离线语音唤醒 + 指令识别（"开始清扫""暂停""返回充电"） |

优先级规则：遥控器 > App > 语音（物理接管权最高），App 和语音可并行。

## 3. 系统模块

系统分为**九大模块**，每个模块封装为一个 ROS2 Node，模块间通过 ROS2 Topic/Service/Action 通信，各自独立开发、独立测试。

### 3.0 统一接口规范（ROS2 基础）

所有模块遵循 ROS2 通信范式：

**Topic（发布/订阅 — 数据流）：**
```yaml
命名规范: {module}/{action}[/{detail}]
QoS: 默认 Sensor Data (Reliable, Volatile, KeepLast)
消息格式: ROS2 .msg 自定义消息
示例:
  - vision/detect/list          # 视觉检测列表
  - lidar/scan/pointcloud       # 预处理点云
  - localization/pose           # 机器人位姿
```

**Service（请求/响应 — 配置与查询）：**
```yaml
命名规范: {module}/get_{param} 或 {module}/set_{param}
QoS: 默认 Services (Reliable, Volatile)
消息格式: ROS2 .srv 自定义服务
示例:
  - cleaning/get_status         # 查询清扫状态
  - motion/set_max_speed        # 设置最大速度
```

**Action（长时任务 — 带进度与取消）：**
```yaml
命名规范: {module}/{task_name}
消息格式: ROS2 .action 自定义动作
示例:
  - planner/navigate_to_goal    # 导航至目标点（含进度反馈）
  - cleaning/execute_cleanup    # 执行清扫（可取消）
```

**配置：**
- 每个节点的参数通过 ROS2 Parameter（YAML 文件加载）注入，不硬编码
- 运行时可通过 `ros2 param` 动态调参

**健康监测：**
- 每个节点发布心跳 Topic（1Hz），携带节点状态 + 故障码
- 利用 ROS2 自带 Node Lifecycle 管理节点生命周期（Unconfigured → Inactive → Active → Finalized）

### 3.1 控制接入模块（新增）

| 项目 | 内容 |
|------|------|
| ROS2 Node | `control_gateway` |
| 定位 | 系统入口，三种控制方式的统一接入与归一化 |
| 功能 | 指令翻译（遥控信号/App指令/语音文本 → 统一指令）、优先级裁决、指令合法性校验、MANUAL 模式下直接运动指令透传 |
| 发布 Topic | `control/cmd/unified`（归一化指令）、`control/cmd/manual_velocity`（MANUAL 模式直接运动指令，优先级最高，→ master_controller 仲裁）、`control/cmd/estop`（可直达运动模块） |
| 订阅 Topic | —（接收硬件的底层驱动不在本模块范围内，通过设备抽象层输入） |
| 提供服务 | `control/set_priority`（运行时调整优先级规则） |
| 优先级 | 遥控器 > App > 语音，指令冲突时高优先级覆盖低优先级，App 和语音可并行 |

**指令集（归一化后）：**

| 指令码 | 含义 | 来源 |
|--------|------|------|
| `START` | 开始清扫 | 遥控/App/语音 |
| `PAUSE` | 暂停清扫 | 遥控/App/语音 |
| `RESUME` | 恢复清扫 | 遥控/App/语音 |
| `STOP` | 停止并待命 | 遥控/App/语音 |
| `RETURN` | 返回充电站 | 遥控/App/语音 |
| `MANUAL` | 手动操控模式 | 遥控/App |
| `SET_AREA` | 设定清扫区域 | App |
| `SET_MODE` | 设定巡航模式 | App/遥控 |
| `ESTOP` | 紧急停止 | 遥控（最高优先级，可直达运动模块） |

### 3.2 主控调度模块

| 项目 | 内容 |
|------|------|
| ROS2 Node | `master_controller` |
| 定位 | 系统大脑，任务调度、状态管理、自动巡航逻辑、运动指令优先级仲裁 |
| 功能 | 接收归一化指令 → 转化为任务调度 → 管理清扫生命周期；运行自动巡航状态机；运动指令仲裁（输入指令优先于路径规划指令）；系统异常处理与降级 |
| 订阅 Topic | `control/cmd/unified`（归一化指令）、`control/cmd/manual_velocity`（遥控/App 直接运动指令，优先级最高）、`planner/cmd/maneuver`（路径规划操控指令）、`planner/status/state`（路径状态）、`planner/output/path`（规划路径，用于状态机跟踪）、`motion/status/fault`、`cleaning/status/dust_full`、`fusion/3d_target`（融合模块 3D 目标告警） |
| 发布 Topic | `master/task/area`、`master/task/mode`、`master/task/clean_strategy`、`master/cmd/motion`（仲裁后统一运动指令：线速度/角速度/急停，→ motion_controller） |
| 提供服务 | `master/get_lifecycle_state`（查询当前状态机状态） |
| Action Client | 调用 `motion/follow_path`（路径跟踪执行）、`planner/navigate_to_goal`（发起导航任务） |
| 生命周期 | 遵循 ROS2 Lifecycle 管理，状态机内部自治 |
| 仲裁规则 | `control/cmd/manual_velocity` > `planner/cmd/maneuver`；`ESTOP` 直达 motion_controller，不经仲裁 |

**自动巡航状态机：**

```
           ┌──────────┐
           │  待命中   │ ← 充电完成 / STOP 指令
           └────┬─────┘
        START↓
           ┌──────────┐
           │  路径规划  │ ← App 设定区域
           └────┬─────┘
        规划完成↓
           ┌──────────┐
      ┌───→│  巡逻巡航  │ ← 发现垃圾则进入清扫
      │    └────┬─────┘
      │ PAUSE↓  ↓RETURN/低电量/尘满
      │    ┌──────────┐     ┌──────────┐
      │    │  暂停    │     │  返航    │
      │    └────┬─────┘     └────┬─────┘
      │ RESUME↓              到达↓
      │    ┌──────────┐     ┌──────────┐
      │    │  定点清扫  │     │  充电中   │
      │    └────┬─────┘     └──────────┘
      │ 清扫完成↓
      └─── 回归巡逻 ──────────────┘
```

### 3.3 路径规划模块

| 项目 | 内容 |
|------|------|
| ROS2 Node | `path_planner` |
| 定位 | 接收清扫区域与地图，计算最优清扫路径；实时获取机器人位姿，输出运动操控指令；接收融合避障决策，执行局部重规划 |
| 功能 | 全局覆盖路径（牛耕式 + 边界回形）、路径跟踪控制（实时位姿→偏差计算→操控指令）、局部避障重规划（融合模块触发）、多区域清扫顺序优化 |
| 订阅 Topic | `master/task/area`（清扫区域任务）、`master/task/mode`（模式切换）、`localization/pose`（实时位姿，路径跟踪输入）、`localization/map/occupancy`（占据栅格地图）、`lidar/obstacle/list`（障碍物列表）、`fusion/obstacle/decision`（融合避障决策） |
| 发布 Topic | `planner/output/path`（目标路径点序列，一次性下发）、`planner/cmd/maneuver`（运动操控指令：线速度/角速度/转向角，持续输出至主控调度）、`planner/status/state` |
| Action Server | `planner/navigate_to_goal`（带进度的导航） |
| 算法 | 全局：Boustrophedon 分解 + TSP（多区域）；局部：DWA / TEB |
| 避障流程 | `fusion/obstacle/decision` 触发局部重规划，路径规划模块决策绕行/等待/减速，通过 `planner/cmd/maneuver` 输出修正指令 |
| 操控指令链路 | `planner/cmd/maneuver` → master_controller 仲裁 → `master/cmd/motion` → motion_controller 执行；若同时有遥控器/App 直接运动指令，以直接指令优先 |

### 3.4 运动模块

| 项目 | 内容 |
|------|------|
| ROS2 Node | `motion_controller` |
| 定位 | 执行机构，响应运动指令 |
| 功能 | 底盘驱动、速度闭环控制、差速转向、急停、坡道辅助 |

| 驱动方式 | 四驱电机 |
| 转向方式 | 差速转弯 |

### 3.6 视觉识别模块

| 项目 | 内容 |
|------|------|
| ROS2 Node | `vision_detector` |
| 定位 | 视觉感知，垃圾检测与分类 |
| 功能 | 垃圾检测与分类、障碍物识别、可通行区域判断 |
| 模型 | YOLO 系列（YOLOv8→v10），目标检测 |
| 订阅 Topic | `sensor/camera/image_raw`（RGB 图像）、`master/task/mode`（模式切换，调整检测策略） |
| 发布 Topic | `vision/detect/list`（检测列表）、`vision/detect/cleanliness`（清洁度）、`vision/detect/drivable`（可通行区域） |
| 提供服务 | `vision/set_model`（热切换模型）、`vision/get_status` |
| 检测类别 | 可回收垃圾、厨余垃圾、有害垃圾、其他垃圾、落叶、烟头、大型障碍物、行人/宠物 |

> 视觉识别模块与训练平台/验证平台形成闭环：训练平台产出模型 → 验证平台评估模型 → 使用平台加载模型。模型文件通过 ROS2 Parameter 指定路径。

### 3.7 清扫模块

| 项目 | 内容 |
|------|------|
| ROS2 Node | `cleaning_actuator` |
| 定位 | 执行机构，执行清扫动作 |
| 功能 | 主刷/边刷控制、吸力调节、洒水量控制、尘满检测 |
| 订阅 Topic | `master/task/clean_strategy`（清扫策略指令）、`vision/detect/list`（垃圾信息）、`vision/detect/cleanliness`（清洁度） |
| 发布 Topic | `cleaning/status/progress`、`cleaning/status/dust_full`、`cleaning/status/brush`、`cleaning/stats/area`、`cleaning/stats/waste_volume` |
| Action Server | `cleaning/execute_cleanup`（可取消的清扫动作） |
| 提供服务 | `cleaning/get_status` |
| 清扫策略 | 覆盖式（全场清扫）、定点式（垃圾密集区）、追踪式（跟随垃圾路径） |
| 联动 | 视觉检测到垃圾 → 主控调度决策 → 清扫模块执行对应策略 → 视觉验证清洁度 → 决定是否重扫 |

### 3.8 激光雷达模块

| 项目 | 内容 |
|------|------|
| ROS2 Node | `lidar_perception` |
| 定位 | 环境感知，三维几何信息获取 |
| 功能 | 环境扫描、障碍物检测与测距、点云预处理（滤波/去畸变/聚类） |
| 订阅 Topic | `sensor/lidar/scan_raw`（LiDAR 原始扫描）、`master/task/mode`（模式切换，调整扫描策略） |
| 发布 Topic | `lidar/scan/pointcloud`（预处理点云）、`lidar/obstacle/list`（障碍物列表+3D位置）、`lidar/cmd/estop` |
| 提供服务 | `lidar/get_status`、`lidar/set_scan_freq` |
| 与定位模块协作 | 发布预处理点云至 `lidar/scan/pointcloud`，定位模块订阅后建图 |
| 与运动模块协作 | **硬直达通道**：`lidar/cmd/estop` Topic 直连运动模块 `motion/cmd/estop`，不经过主控链路 |
| 与融合模块协作 | 发布 `lidar/scan/pointcloud` 和 `lidar/obstacle/list` 至融合模块，由融合模块完成视觉+LiDAR后融合 |

### 3.9 后融合模块

| 项目 | 内容 |
|------|------|
| ROS2 Node | `fusion_engine` |
| 定位 | 视觉+LiDAR后融合，将 2D 检测框与 3D 点云空间关联，输出避障决策 |
| 功能 | 2D 检测框→点云映射、空间关联匹配、3D 目标位置与尺寸估算、障碍物分类判定（绕行/清扫/等待） |
| 订阅 Topic | `vision/detect/list`（视觉 2D 检测框）、`lidar/scan/pointcloud`（预处理点云）、`lidar/obstacle/list`（LiDAR 障碍物列表） |
| 发布 Topic | `fusion/3d_target`（3D 目标信息+告警，→ master_controller）、`fusion/obstacle/decision`（避障决策，→ path_planner）、`fusion/status`（融合模块状态） |
| 提供服务 | `fusion/get_status` |
| 生命周期 | 遵循 ROS2 Lifecycle；视觉 Topic 超时时降级为纯 LiDAR 模式（仅转发 obstacle/list，不产出 3d_target） |
| 融合策略 | 视觉识别类别 + LiDAR 三维尺寸联合判定：road_obstacle/pedestrian_pet 且 LiDAR 确认需绕行 → `fusion/obstacle/decision` 携带避障指令；垃圾类别 + 小尺寸 → 交由清扫模块处理，不触发避障 |
| 与路径规划协作 | `fusion/obstacle/decision` → path_planner 订阅后执行局部避障重规划 |
| 与主控调度协作 | `fusion/3d_target` → master_controller 订阅后判断紧急程度，必要时触发全局调度干预 |

### 4.2 消息主题总览（ROS2 通信清单）

```text
# ===== 控制流 (control_gateway → master_controller) =====
control/cmd/unified          # Topic: 归一化指令 (CleaningCommand.msg)
control/cmd/manual_velocity  # Topic: MANUAL 模式直接运动指令 (Twist.msg)，优先级最高
control/cmd/estop            # Topic: 紧急停止，可直达 motion_controller

# ===== 主控调度流 (master_controller → 各模块) =====
master/task/area             # Topic: 清扫区域任务
master/task/mode             # Topic: 模式切换 (CRUISE/CLEAN/RETURN)
master/task/clean_strategy   # Topic: 清扫策略选择
master/cmd/motion            # Topic: 仲裁后统一运动指令 (Twist.msg → motion_controller)
master/planner/navigate_to_goal  # Action Client: 调用 path_planner 发起导航
master/motion/follow_path    # Action Client: 调用 motion_controller 执行路径跟踪

# ===== 路径规划流 (path_planner) =====
planner/input/pose            # 订阅: localization/pose (实时位姿)
planner/input/map             # 订阅: localization/map/occupancy
planner/input/obstacles       # 订阅: lidar/obstacle/list
planner/input/fusion          # 订阅: fusion/obstacle/decision
planner/output/path           # Topic: 发布目标路径点序列 (Path.msg → master_controller)
planner/cmd/maneuver          # Topic: 运动操控指令 (Twist.msg → master_controller 仲裁)
planner/status/state          # Topic: 路径执行状态
planner/navigate_to_goal      # Action Server: 导航至目标点（由 master_controller 调用）

# ===== 运动流 (motion_controller) =====
motion/odom                   # Topic: 里程计 (Odometry.msg)
motion/status/motor           # Topic: 电机状态
motion/status/fault           # Topic: 故障码
motion/cmd/estop              # Topic: 急停订阅（来自 lidar + control，硬直达）
```

## 6. 架构原则

- **模块独立**：九大模块各自封装为 ROS2 Node，独立开发、独立测试，通过 Topic/Service/Action 解耦通信
- **平台分离**：训练/验证/使用三个平台无运行时依赖，仅共享模型文件和配置
- **配置驱动**：模型结构、清扫策略、控制参数均通过 ROS2 Parameter（YAML）控制，支持 `ros2 param` 运行时调参
- **生命周期管理**：各节点使用 ROS2 Lifecycle 管理，从 Unconfigured → Inactive → Active，支持优雅启停
- **可扩展**：新增传感器、控制方式、功能模块，增加 ROS2 Node 即可，无需修改现有节点

## 7. 方案选型论证：纯 LiDAR 避障 vs Camera+LiDAR 混合

### 7.1 环卫场景的特殊性

与自动驾驶不同，环卫机器人面临的挑战：
- 需要**分类垃圾**（可回收/不可回收/有害），纯几何信息无法区分
- 需要判断**清洁度**（地面是否干净），这是视觉任务
- 低速运行（≤1.5m/s），对远距离感知要求低，对近距离语义要求高
- 场景包括室内（走廊/大厅）和半室外（园区/人行道），GPS 不可靠

### 7.2 关键场景对比

| 场景 | 纯 LiDAR | Camera + LiDAR |
|------|----------|----------------|
| 区分烟头 vs 地砖缝隙 | 无法区分 | YOLO 视觉识别 |
| 湿垃圾 vs 水渍 | 形状均不规则 | 颜色/纹理区分 |
| 玻璃门前避障 | 激光透射，可能漏检 | Camera 识别门框/玻璃 |
| 黑色地面/地毯 | LiDAR 吸收激光，数据缺失 | Camera 不受影响 |
| 强光/逆光 | 不受影响 | Camera 短暂致盲，LiDAR 接管 |
| 夜间户外清扫 | LiDAR 可避障但无法分类垃圾 | Camera 红外模式辅助 |

### 7.3 结论

混合方案为项目基础路线。环卫场景对垃圾**分类**和**清洁度判断**是刚性需求——纯 LiDAR 无法满足。Camera 负责"这是什么垃圾"，LiDAR 负责"它在什么位置、距离多远"。
