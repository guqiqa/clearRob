> 来源：智能环卫机器人控制系统需求文档 V2.5

> 更新：2026-06-16

## 1. 模块定位与职责边界

### 1.1 定位

`control_gateway` 是系统唯一入口，负责三种控制方式（遥控器、App、语音）的统一接入与归一化处理。所有对机器人的操作指令必须经过本模块翻译为归一化指令后再下发，保证指令来源对下游模块透明。

### 1.2 职责边界

| 属于本模块 | 不属于本模块 |
|-----------|-------------|
| 遥控器信号解码 → 归一化指令 | 遥控器硬件驱动（设备抽象层提供） |
| App 指令解析与合法性校验 | App 端 UI/网络通信（App 后端负责） |
| 语音文本 → 指令码映射 | 语音唤醒/ASR 引擎（设备抽象层提供） |
| 三源优先级裁决 | 指令执行（master_controller 负责） |
| MANUAL 模式速度指令透传 | 底盘驱动执行（motion_controller 负责） |
| ESTOP 硬直达通道 | ESTOP 的物理执行 |

### 1.3 系统定位示意

```
遥控器 ──(RF/Bluetooth)──→ 设备抽象层 ──→ control_gateway
App     ──(WiFi/4G)──────→ 设备抽象层 ──→ control_gateway
语音    ──(麦克风)───────→ 设备抽象层 ──→ control_gateway
                                          │
                    ┌─────────────────────┼─────────────────────┐
                    ↓                     ↓                     ↓
            control/cmd/unified   control/cmd/manual_velocity  control/cmd/estop
            (master_controller)   (master_controller仲裁)      (motion_controller硬直达)
```

## 2. ROS2 接口规范

### 2.1 Node 信息

| 项目 | 内容 |
|------|------|
| ROS2 Node | `control_gateway` |
| 命名空间 | `/`（全局，作为系统入口不使用子命名空间） |
| 语言 | C++17（低延迟，实时性保障） |
| 生命周期 | ROS2 Managed Lifecycle（Unconfigured → Inactive → Active） |

### 2.2 订阅

| Topic | 消息类型 | QoS | 说明 |
|-------|---------|-----|------|
| `device/rc/raw` | `cleaning_robot_interfaces/msg/RCRawSignal` | Sensor Data, KeepLast(1) | 遥控器解码后原始信号（设备抽象层输出） |
| `device/app/cmd` | `cleaning_robot_interfaces/msg/AppCommand` | Sensor Data, KeepLast(1) | App 下发的结构化指令（设备抽象层输出） |
| `device/voice/text` | `std_msgs/msg/String` | Sensor Data, KeepLast(1) | 语音识别文本（设备抽象层输出） |
| `device/rc/velocity` | `geometry_msgs/msg/Twist` | Sensor Data, KeepLast(1) | 遥控器摇杆原始速度信号（MANUAL 模式） |
| `device/app/velocity` | `geometry_msgs/msg/Twist` | Sensor Data, KeepLast(1) | App 虚拟摇杆速度信号（MANUAL 模式） |

### 2.3 发布

| Topic | 消息类型 | 频率 | 说明 |
|-------|---------|------|------|
| `control/cmd/unified` | `cleaning_robot_interfaces/msg/UnifiedCommand` | 事件驱动（收到指令时立即发布） | 归一化指令 |
| `control/cmd/manual_velocity` | `geometry_msgs/msg/Twist` | 与遥控器/App 摇杆频率同步（≤50Hz） | MANUAL 模式直接运动指令透传 |
| `control/cmd/estop` | `cleaning_robot_interfaces/msg/MotionCommand` | 事件驱动（仅按下/抬起急停时发布） | 紧急停止指令，直达 motion_controller |
| `control/status` | `cleaning_robot_interfaces/msg/VisionStatus` | 1Hz | 模块运行状态（复用 VisionStatus 格式） |
| `system/heartbeat/control_gateway` | `cleaning_robot_interfaces/msg/Heartbeat` | 1Hz | 心跳 |

### 2.4 Service

| Service | 类型 | 说明 |
|---------|------|------|
| `control/set_priority` | `cleaning_robot_interfaces/srv/SetPriority` | 运行时调整优先级规则 |

### 2.5 自定义消息（新增）

```ros2
# RCRawSignal.msg — 遥控器解码后信号
# 由设备抽象层发布
std_msgs/Header  header
uint8[]          buttons             # 按下的按键编号列表（多键可同时按）
float32[]        axes                # 摇杆/拨轮轴值列表（-1.0~1.0）
uint8            signal_strength     # 信号强度 0~100（%）
bool             connected           # 遥控器是否已连接
```

```ros2
# AppCommand.msg — App 下发的结构化指令
# 由设备抽象层发布
std_msgs/Header  header
string           command             # "START"/"PAUSE"/"RESUME"/"STOP"/"RETURN"/"MANUAL"/"SET_AREA"/"SET_MODE"
string           params_json         # 指令附参 JSON 字符串 {"area_id":"xxx","mode":"CLEAN",...}
string           request_id          # 请求 ID（用于 App 端追踪），UUID 格式
```

## 3. 功能需求详述

### 3.1 指令翻译（原始信号 → 归一化指令）

**功能描述：** 将三种来源的原始输入翻译为 `UnifiedCommand.msg` 格式，对下游模块完全透明。

**指令码定义（归一化后）：**

| 指令码 (uint8) | command_name | 含义 | 来源 |
|---------------|-------------|------|------|
| 0 | `START` | 开始清扫 | 遥控/App/语音 |
| 1 | `PAUSE` | 暂停清扫 | 遥控/App/语音 |
| 2 | `RESUME` | 恢复清扫 | 遥控/App/语音 |
| 3 | `STOP` | 停止并待命 | 遥控/App/语音 |
| 4 | `RETURN` | 返回充电站 | 遥控/App/语音 |
| 5 | `MANUAL` | 手动操控模式 | 遥控/App |
| 6 | `SET_AREA` | 设定清扫区域 | App |
| 7 | `SET_MODE` | 设定巡航模式 | App/遥控 |
| 9 | `ESTOP` | 紧急停止 | 遥控（最高优先级） |

**翻译规则（遥控器）：**

| 遥控器物理操作 | 归一化指令 | 条件 |
|--------------|-----------|------|
| 短按"清扫"键(< 1s) | START | 当前状态 待命中 or 暂停中 |
| 短按"清扫"键(< 1s) | PAUSE | 当前状态 巡航中 or 清扫中 |
| 长按"清扫"键(≥ 2s) | STOP | — |
| "返航"键 | RETURN | — |
| 同时按下 L1+R1 拨片 | ESTOP | 物理组合防误触 |
| 拨动模式旋钮 | SET_MODE | 旋钮位置 → 模式值 |
| 摇杆非零（已在 MANUAL 模式下） | 透过 manual_velocity | 不生成归一化指令，直接发布速度 Topic |

**翻译规则（App）：**

| App 操作 | 归一化指令 | params[] 填充 |
|----------|-----------|--------------|
| 点击"开始清扫" | START | 空 |
| 点击"暂停" | PAUSE | 空 |
| 点击"恢复" | RESUME | 空 |
| 点击"停止" | STOP | 空 |
| 点击"返回充电" | RETURN | 空 |
| 滑动进入手动模式 | MANUAL | 空 |
| 在地图上选点/画区 | SET_AREA | [0]=area_id（UUID） |
| 选择巡航模式 | SET_MODE | [0]=mode（0=CRUISE 1=CLEAN 2=RETURN） |

**翻译规则（语音）：**

| 语音文本匹配 | 归一化指令 | 匹配方式 |
|------------|-----------|----------|
| "开始清扫""启动""开工" | START | 关键词匹配（不区分大小写） |
| "暂停""等一下""停一下" | PAUSE | 关键词匹配 |
| "继续""恢复""接着扫" | RESUME | 关键词匹配 |
| "停止""停""别扫了" | STOP | 关键词匹配 |
| "回去""返回""充电" | RETURN | 关键词匹配 |

---

### 3.2 优先级裁决

**功能描述：** 当多源同时发送指令时，按优先级规则选择最终指令发布。

**优先级规则（默认配置，运行时可通过 Service 调整）：**
```
遥控器（source=0） > App（source=1） > 语音（source=2）
```

**裁决规则：**
1. 遥控器与 App/语音指令冲突：遥控器指令胜出，低优先级指令丢弃（不排队）
2. App 与语音指令并行但不冲突（同一指令码）：仅发布一条，优先 App
3. App 与语音指令并行且冲突（不同指令码）：App 胜出，语音指令丢弃
4. ESTOP 指令不参与裁决：**绕过优先级机制，直接发布至 `control/cmd/estop`**，无论当前任何模式
5. MANUAL 模式下的持续速度指令（`control/cmd/manual_velocity`）不与离散指令冲突——MANUAL 期间 START/PAUSE 等离散指令仍可下发

**裁决时间窗口：** 指令在 50ms 窗口内到达视为"同时"（覆盖同一 ROS2 消息帧间隔）。

---

### 3.3 指令合法性校验

**功能描述：** 每条归一化指令在发布前必须通过合法性校验，不合法指令丢弃并记录。

**校验规则：**

| 校验项 | 条件 | 不合法时行为 |
|--------|------|-------------|
| source 有效性 | source ∈ {0,1,2} | 丢弃，日志 ERROR |
| command 有效性 | command_name 在指令表内 | 丢弃，日志 WARN |
| SET_AREA 参数完整性 | params[0] 非空且为有效 UUID 格式 | 丢弃，日志 WARN + 向 App 返回 NACK（通过 status 发布） |
| SET_MODE 参数完整性 | params[0] ∈ {0,1,2} | 丢弃，日志 WARN |
| 重复指令过滤 | 与上一条指令完全相同（command+source+params）且间隔 < 200ms | 丢弃，视作重复发送 |
| 语音置信度 | 语音识别文本附带置信度 < 0.6 | 丢弃，不生成指令（防止误触发） |

---

### 3.4 MANUAL 模式速度透传

**功能描述：** MANUAL 模式下，遥控器/App 的速度信号直接透传至 `control/cmd/manual_velocity`，由 master_controller 仲裁后下发 motion_controller。

**处理流程：**
```
遥控器摇杆 → device/rc/velocity (Twist) → control_gateway
    │
    ├── 当前模式=MANUAL → 直接转发至 control/cmd/manual_velocity
    │
    └── 当前模式≠MANUAL → 丢弃（速度指令仅在 MANUAL 模式有效）
```

**透传规则：**
- 线速度映射：摇杆 Y 轴 -1.0~1.0 → -max_linear_velocity ~ +max_linear_velocity
- 角速度映射：摇杆 X 轴 -1.0~1.0 → -max_angular_velocity ~ +max_angular_velocity
- 遥控器和 App 同时发送速度信号时：遥控器优先（遥控制摇杆覆盖 App 虚拟摇杆）
- 透传频率：与输入频率同步，最高 50Hz，超出则降采样

---

### 3.5 ESTOP 硬直达

**功能描述：** 遥控器触发急停时，`control/cmd/estop` 直达 motion_controller，不经过 master_controller 仲裁。

**触发条件：** 遥控器 L1+R1 拨片同时按下（持续 ≥ 100ms 防抖动）

**解除条件：** 遥控器 L2+R2 拨片同时按下（持续 ≥ 100ms）

**处理逻辑：**
1. 急停按下：发布 `MotionCommand(estop=true)` 至 `control/cmd/estop`
2. 急停解除：发布 `MotionCommand(estop=false)` 至 `control/cmd/estop`
3. 同时发布一条 `UnifiedCommand(command=ESTOP, source=0)` 至 `control/cmd/unified` 通知 master_controller 记录状态
4. ESTOP 期间不阻断其他指令的归一化处理（master_controller 自行忽略或排队 ESTOP 期间的指令）

## 4. 模式管理

### 4.1 当前运行模式

本模块维护一个全局运行模式变量，影响 MANUAL 速度指令的转发行为：

| 模式 | 来源指令 | 速度透传 | 说明 |
|------|---------|----------|------|
| AUTO | START / RESUME（初始化默认） | 不转发 | 自动巡航中，忽略摇杆速度输入 |
| MANUAL | MANUAL 指令 | 转发 | 手动操控中，摇杆速度 → manual_velocity |
| ESTOP | ESTOP 指令 | 不转发 | 急停中，所有运动指令阻断 |

### 4.2 模式切换

- AUTO → MANUAL：收到 MANUAL 指令 + 合法来源校验
- MANUAL → AUTO：收到 START / RESUME / STOP / RETURN 任一指令
- 任何模式 → ESTOP：遥控器急停触发
- ESTOP → AUTO（IDLE 待命）：遥控器急停解除 + 自动复位

## 5. 配置参数（ROS2 Parameter YAML）

```yaml
control_gateway:
  ros__parameters:
    # 优先级
    default_priority_rule: "RC_APP"       # "RC_ONLY" / "RC_APP" / "ALL"
    
    # 指令
    dedup_interval_ms: 200                # 重复指令过滤窗口 (ms)
    arbitration_window_ms: 50             # 多源裁决时间窗口 (ms)
    voice_confidence_threshold: 0.6       # 语音指令最低置信度
    
    # MANUAL 速度映射
    max_linear_velocity: 1.5              # 最大线速度 m/s
    max_angular_velocity: 2.0             # 最大角速度 rad/s
    max_velocity_publish_rate: 50.0       # 速度指令最大发布频率 Hz
    
    # ESTOP
    estop_debounce_ms: 100                # 急停按键防抖延迟 (ms)
    estop_release_button_combo: [4, 5]   # 解除急停按键组合（L2+R2）
```

## 6. 异常处理

| 故障场景 | 检测方式 | 响应行为 |
|----------|----------|----------|
| 遥控器断连 | `RCRawSignal.connected == false` 持续 > 3s | 自动切换到 App/语音模式（按优先级规则），发布 status 告警 |
| App 连接断开 | `device/app/cmd` 超时 > 30s 无消息 | 不影响遥控器和语音输入，发布 status 告警 |
| 遥控器信号干扰（大量噪声） | 1s 内收到 >20 条矛盾指令（如 START 后 200ms 内 STOP） | 将遥控器标记为"不可靠"，降级优先级为最低，发布 WARN |
| 设备抽象层超时 | 任意输入 Topic `device/*` > 5s 无消息 | 该输入源标记为不可用，不影响其他源 |
| 语音持续误触发 | 10s 内 >5 条不合法语音指令 | 语音输入静音 60s，60s 后自动恢复 |
| 内部状态不一致 | — | 所有指令统一排队处理，单线程串行化，避免竞态 |

## 7. 关键交互序列

### 7.1 正常指令流

```
遥控器/App/语音 → device/* (设备抽象层) → control_gateway
                                               │
                                        合法性校验 + 翻译
                                               │
                                        优先级裁决
                                               │
                                    control/cmd/unified → master_controller
```

### 7.2 MANUAL 速度指令流

```
遥控器摇杆 → device/rc/velocity → control_gateway
                                     │
                                  模式=MANUAL?
                                     │
                              是 → control/cmd/manual_velocity → master_controller 仲裁
                              否 → 丢弃
```

### 7.3 ESTOP 直达流

```
遥控器 L1+R1 → device/rc/raw → control_gateway
                                  │
                           防抖确认 (100ms)
                                  │
                        ┌─────────┴─────────┐
                        ↓                   ↓
            control/cmd/estop      control/cmd/unified
            → motion_controller    → master_controller
              (硬直达执行急停)        (通知记录状态)
```
