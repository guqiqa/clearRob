# 双目原生取样转向计划

更新时间：2026-08-24

## 1. 当前结论

暂停将双路 H.264 通过 Python/OpenCV 软件解码后发布到 ROS2 的正式路线。开发板上遗留的左右解码进程各占用约 112% CPU，双路合计超过两个 CPU 核心，并伴随每个进程约 154 MB RSS，不适合作为后续双目测距和 SLAM 的长期输入。

VPU 暂不作为当前解决方向。现有系统中 `vpu_v4l2` 未启用，MediaCodec 曾报告 `vdec_render isn't ready`，继续调试 VPU 会阻塞双目取样主线。NPU/BPU 继续保留给视觉识别推理。

正式方向调整为：

```text
CameraManager::subscribeStereo()
    -> StereoFrameSynchronizer
    -> 左右原生 NV12 FrameHandle
    -> 直接提取 Y 平面
    -> ROS2 mono8 图像
```

## 2. 已确认的板端事实

- 当前硬件实际使用左目 `sensor=4`、右目 `sensor=5`。
- `S90cam-service.service` 的启动参数和 `bestmow-stereo-h264.service` 实际拉起的 `multi_pipe_vin_isp_vse` 均证明使用的是 4/5。
- 原生相机发布包示例配置使用左目 1、右目 0，属于另一套板卡映射，不能直接用于当前开发板。
- SC132GS SDK 会将配置中的 `m_nSensorIndex` 原样传给 `X5CameraAdapter`，因此需要建立当前开发板专用的 4/5 配置。
- 原生 SDK 运行时必须将 `/usr/hobot/lib/sensor` 加入 `LD_LIBRARY_PATH`。
- 历史报告显示单路图像可以稳定输出，但真实双目时间差可能超过 5 ms。因此“正常取样”和“同步合格”必须分开验收。

## 3. 新执行顺序

### 3.1 清理软件解码链路

停止遗留的 `s90_h264_input` ROS2 launch 和左右解码节点，确认 CPU 占用恢复。保留代码作为预览回退，但不作为正式双目输入。

### 3.2 使用官方工具验证底层取样

暂不先修改或启动自研 ROS2 原生节点。优先使用 SDK 权威测试程序：

```text
/opt/bestmow/native_camera/releases/20260820-x5-native-v1/build-x5/bin/camera_shared_test
```

测试前停止以下相机所有者并确认相关进程完全退出：

```text
S90cam-service.service
camera-preview.service
bestmow-stereo-h264.service
cam-service
multi_pipe_vin_isp_vse
camera-preview-server
```

按以下顺序测试：

1. 使用当前板专用配置测试 `sensor=4` 单目 10 秒。
2. 使用当前板专用配置测试 `sensor=5` 单目 10 秒。
3. 两路单目均通过后，测试 4/5 双目 30 秒。
4. 保存程序日志、内核日志、帧率、尺寸、时间戳、CPU 和 RSS。

### 3.3 接入 ROS2

只有 `camera_shared_test` 确认两路都能正常出帧后，才执行以下工作：

- 将 `native_stereo_camera` 调整为左目 4、右目 5。
- 保留原生 NV12，不做 H.264 编解码。
- 直接复制 NV12 Y 平面并发布 `mono8`。
- 发布 `camera_native/left/image_raw`、`camera_native/right/image_raw` 和 `camera_native/stereo/status`。
- 使用原始左右时间戳和 `delta_ns`，不以 ROS2 到达时间代替传感器时间戳。

## 4. 分级验收

### A. 正常取样

- 左右目分别持续出帧，均不低于 14 FPS。
- 图像尺寸、步长和数据长度一致且正确。
- 左右画面内容不同，方向和物理映射固定。
- 时间戳单调递增，无回退。
- 运行过程无 ISP/VIN/VSE 错误和进程异常退出。

### B. 双目同步

- 配对率不低于 99%。
- 左右原始时间差 p99 不超过 5 ms。
- 不允许通过放宽到 80 ms 或改用软件到达时间掩盖硬件不同步。

只有 A 通过后才处理 B。A、B 均通过后，才恢复标定、StereoSGBM 和 SLAM 工作。

## 5. 失败处理和回退

如果官方 `camera_shared_test` 使用 4/5 配置仍在 `create_isp_node` 返回 `ret=-10`：

1. 停止继续修改 ROS2 节点和深度算法。
2. 保存 `camera_shared_test` 日志、`journalctl` 和 `dmesg`。
3. 向板卡或相机 SDK 厂商确认 sensor 4/5 对应的 VIN、ISP、VSE 配置及资源释放流程。
4. 恢复 `S90cam-service.service` 和预览服务，用于观察画面，但不恢复双路软件解码常驻进程。

## 6. 后续阶段

正常取样和同步验收通过后，执行顺序保持为：

```text
原生双目取样
-> ROS2 mono8 发布
-> 7x10 内角点、20 mm 棋盘格标定
-> StereoSGBM 深度和 ROI 测距
-> 双目视觉里程计
-> RTAB-Map 2D 栅格地图
```

双目深度主要用于 SLAM 建图；毫米波雷达继续负责避障。
