## 3. CAN 总线通信协议（已解析）

### 3.1 物理层

| 参数 | 值 |
|------|------|
| 接口 | `can0` (SocketCAN) |
| 波特率 | 500 Kbps |
| 帧类型 | 标准数据帧（11-bit ID） |

### 3.2 电机 CAN ID 分配

| CAN ID | 电机 | 功能 |
|:---:|------|------|
| `001` | 左后轮 | 行走驱动 |
| `002` | 左前轮 | 行走驱动 |
| `003` | 右后轮 | 行走驱动 |
| `004` | 右前轮 | 行走驱动 |
| `005` | 刀盘 | 切割/清扫 |

### 3.3 指令格式

**电流控制帧（DLC = 3）：**

```
DATA[0] = 0x01      （电流控制）
DATA[1] = 高 8 位    \
DATA[2] = 低 8 位    /  int16 电流值（单位：10mA），正=正转，负=反转
```

**心跳帧（DLC = 1）：**

```
DATA[0] = 0x00      （心跳，需周期发送）
```

### 3.4 实测数据

```
静止:    001 [3] 01 00 00   电流 0
慢速前进: 001 [3] 01 00 64   电流 +1.0A
快速前进: 001 [3] 01 01 F4   电流 +5.0A
后退:    001 [3] 01 FF 9C   电流 -1.0A
转向:    001/003 [3] 01 00 64   左侧正转 +1.0A
         002/004 [3] 01 FF 9C   右侧反转 -1.0A
```

### 3.5 通信周期

每台电机交替发送心跳和电流帧，周期约 5-10ms。编组模式为轮询：001→003→002→004→005→001（心跳）→003（心跳）→...

### 3.6 查询指令协议（已解析）

**查询命令帧（DLC = 2）：**

```
DATA[0] = 0x0F      （查询指令）
DATA[1] = 查询码     （0x00–0x09）
```

**查询响应帧：CANID 不变，DATA[0]=0x0F，DATA[1]=查询码回显，DATA[2..]=数据**

| 查询码 | 信息 | 响应 DLC | 数据位置 | 数据类型 | 单位 | 用途 |
|:---:|------|:---:|------|------|------|------|
| `00` | 故障信息 | 4 | DATA[2:4] | int16 | — | 故障监控 |
| `01` | **当前转速** | 6 | DATA[2:6] | **int32** | erpm | **里程计** |
| `02` | 占空比 | 4 | DATA[2:4] | int16 | 0.1% | 调试 |
| `03` | 功率 | 4 | DATA[2:4] | int16 | W | 监控 |
| `04` | 电压 | 4 | DATA[2:4] | int16 | V | 监控 |
| `05` | 电机电流 | 4 | DATA[2:4] | int16 | 10mA | 监控 |
| `06` | 总线电流 | 4 | DATA[2:4] | int16 | 10mA | 监控 |
| `07` | **温度** | 4 | DATA[2:4] | int16 | °C | 过热保护 |
| `08` | 绝对位置 | 6 | DATA[2:6] | int32 | 0.01° | 标定 |
| `09` | 单圈角度 | 4 | DATA[2:4] | int16 | 0.01° | 标定 |

**查询示例：**

```
查询 ID=1 的转速:
  发送: 01 [2] 0F 01
  响应: 01 [6] 0F 01 00 00 13 88    → 0x1388 = 5000 erpm

查询 ID=2 的故障:
  发送: 02 [2] 0F 00
  响应: 02 [4] 0F 00 00 00           → 无故障
```

### 3.7 里程计计算公式

```python
# 参数（已确认）
POLE_PAIRS = 10          # 电机磁极对数 (20极/2)
GEAR_RATIO = 5.2         # 减速比 (5.2:1)
WHEEL_RADIUS = 0.08      # 轮半径 (160mm/2)
TRACK_WIDTH = 0.53       # 轮距 (530mm)

def erpm_to_ms(erpm):
    rpm_motor = erpm / POLE_PAIRS          # 电转速 → 电机机械转速 (rpm)
    rpm_wheel = rpm_motor / GEAR_RATIO     # → 轮转速 (5.2:1 减速)
    rad_s = rpm_wheel * 2 * 3.14159265 / 60  # → rad/s
    return rad_s * WHEEL_RADIUS            # → m/s

# 周期查询左右前轮转速 (CAN ID: 002=左前, 004=右前)
v_left  = erpm_to_ms(query_speed(can_id=2))
v_right = erpm_to_ms(query_speed(can_id=4))

# 差速模型 → 机器人速度
v = (v_right + v_left) / 2              # 线速度 (m/s)
ω = (v_right - v_left) / TRACK_WIDTH    # 角速度 (rad/s)

# 里程计积分 (dt = 查询周期)
θ += ω * dt
x += v * cos(θ) * dt
y += v * sin(θ) * dt
```

### 3.8 IMU 驱动代码（手册提供）

**数据结构（24 字节）：**

```c
struct qmi8658_frame {
    int32_t ax;   // X 轴加速度, /1000000.0 = m/s²
    int32_t ay;   // Y 轴加速度, /1000000.0 = m/s²
    int32_t az;   // Z 轴加速度, /1000000.0 = m/s²
    int32_t gx;   // X 轴角速度, /1000000.0 = rad/s
    int32_t gy;   // Y 轴角速度, /1000000.0 = rad/s
    int32_t gz;   // Z 轴角速度, /1000000.0 = rad/s
};
```

**读取方式：**

```c
int fd = open("/dev/qmi8658_imu", O_RDONLY);
struct qmi8658_frame frm;
ssize_t n = read(fd, &frm, sizeof(frm));  // 阻塞读取, 24 字节
```

**校准系数（手册提供，与 Robot.yaml 一致）：**

```python
ax = ax / 1e6 + 0.320
ay = ay / 1e6 + 0.027
az = (az / 1e6 + 0.802) * 0.991
gx = gx / 1e6 + 0.0265
gy = gy / 1e6 - 0.0135
gz = gz / 1e6 + 0.0132
```

## 6. 暂定规划：三期实施

### 6.1 第一期 —— 底盘打通（无需新增硬件）

**目标**: 自主控制底盘行驶，建立 ROS 2 数据链路。

**技术方案**: 基于 Python-CAN + ROS 2 Humble ros-base，编写 4 个驱动节点 + 1 个主控节点。

```
        ┌──────────────────────────────────────────────────────┐
        │  第一期节点拓扑                                        │
        │                                                      │
        │  /dev/qmi8658_imu ──→ imu_driver ──→ /imu/data       │
        │  /dev/ttyS2       ──→ rtk_driver ──→ /fix             │
        │  遥控器 SBUS      ──→ remote_driver ──→ /joy          │
        │  can0             ←→ chassis_driver ←→ /cmd_vel, /odom│
        │                       ↑                              │
        │                       └── master_bridge               │
        │                          (遥控→底盘 / 手动模式)        │
        └──────────────────────────────────────────────────────┘
```

| 节点 | 功能 | 代码量 |
|------|------|:---:|
| `imu_driver` | 读 `/dev/qmi8658_imu` → 解析 QMI8658 结构体 → 发布 `sensor_msgs/Imu` | ~100 行 |
| `rtk_driver` | 读 `/dev/ttyS2` → NMEA 解析 → 发布 `sensor_msgs/NavSatFix` | ~80 行（nmea_navsat_driver 已有） |
| `remote_driver` | SBUS 直连直读 → 解析 16 通道 → 发布 `sensor_msgs/Joy` | ~60 行 |
| `chassis_driver` | 订阅 `/joy` + `/cmd_vel` → CAN 电流控制 → CAN 查询转速 → 发布 `/odom` | ~200 行 |

**产出**: 
- 遥控器控制底盘（已有功能，改为 ROS 2 链路）
- PC 端 RViz2 实时显示 IMU/RTK/里程计
- 验证 ROS 2 全链路通信

**前置条件**: 
- [x] CAN 协议已解析（电流控制 + 查询 + 心跳）
- [x] 电机参数已确认（极对数 4、轮距 530mm、轮径 160mm）

### 6.2 第二期 —— 毫米波雷达 + 视觉融合感知（暂定方案）

**目标**: 加装毫米波雷达 + 启用摄像头 + BPU AI 推理，实现全天候避障 + 垃圾识别 + 全自主清扫作业。

**新增硬件**: 
- 毫米波雷达（型号待定，TI IWR/AWR 系列或大陆 ARS 系列，**2D 雷达，无俯仰角/高度信息**）
- 摄像头模组（确认 MIPI CSI 连接状态）

**传感器特性说明**: 

| 传感器 | 输出 | 不提供 | 分工 |
|--------|------|--------|------|
| 毫米波雷达 (2D) | 距离、方位角、径向速度（多普勒） | **高度/俯仰角** | 全天候几何障碍检测 + 运动目标追踪 |
| 摄像头 + BPU | 2D 检测框 + 类别 + 可通行区域 | 精确深度 | 语义理解（是什么）+ 高度推断（检测框尺寸） |

**说明**: 
- 不采用 2D 激光雷达方案。2D 毫米波雷达负责实时避障（全天候、不受雨雾灰尘影响，多普勒直接测速），摄像头 + BPU 负责语义理解（垃圾分类、清洁度判断、可通行区域）并**补偿雷达缺失的高度信息**。
- 雷达缺失高度的影响：无法区分低矮可穿越物体（路面减速带）与高障碍物（墙体），需摄像头辅助判断；无法检测悬空障碍物（限高杆等），环卫场景影响较小。
- 定位方案：轮式里程计 + IMU + RTK 融合（不依赖激光 SLAM）。
- 若后期需要建图能力，可补充 4D 毫米波雷达或激光雷达。

**技术方案**:

```
        ┌──────────────────────────────────────────────────────┐
        │  第二期节点拓扑                                        │
        │                                                      │
        │  毫米波雷达 ──→ radar_driver ──→ /radar/obstacles     │
        │                           ↓                          │
        │  摄像头 ──→ vision_detector (BPU YOLO)               │
        │                ↓              ↓                      │
        │        /vision/detect   /vision/drivable             │
        │                ↓              ↓                      │
        │        ┌──────────────────────┐                      │
        │        │  fusion_engine       │                      │
        │        │  雷达+视觉后融合      │                      │
        │        └──────┬───────────────┘                      │
        │               ↓                                      │
        │        /obstacle/decision  (避障决策)                 │
        │               ↓                                      │
        │        Nav2 local_costmap                            │
```

## 10. 架构原则

- **不依赖厂商闭源程序**：每个硬件设备从底层驱动，协议公开可验证
- **模块独立**：每个驱动/功能节点为独立 ROS 2 Node，可单独启停、调试
- **共享模块管理**：`cleaning_robot_common` 包统一管理全局常量（CAN ID、电机参数、Topic 名称、校准系数）——所有节点 `import` 同一份配置，消除散落重复定义
- **纯函数运动学**：差速模型、里程计积分等公式封装为无状态纯函数，可独立单元测试
- **分布式调试**：设备跑计算，PC 跑 RViz2 显示
- **分期交付**：每期有可运行、可演示的产出
- **配置驱动**：所有参数通过 ROS 2 Parameter (YAML) 注入，不硬编码
