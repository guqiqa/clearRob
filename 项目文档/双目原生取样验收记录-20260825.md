# 双目原生取样验收记录

更新时间：2026-08-25

## 当前结论

阶段一尚未通过，暂不启动 `native_stereo_camera`、`stereo_depth` 或 RTAB-Map。

## 关键映射

`camera_shared_test` 使用的是 X5 CameraManager API 的 sensor index，不是底层
`multi_pipe_vin_isp_vse` 的 VIN 编号。SDK 源码中的 `vp_sensor_config_list` 只有两个
合法索引：

- API index `1`：物理左目，SC132GS V2 左 GDC
- API index `0`：物理右目，SC132GS V2 右 GDC

底层服务命令中的 `sensor=4/5` 不能直接填入 `m_nSensorIndex`；填入 4 会得到：
`[X5CameraAdapter] Unsupported sensor index 4`。

## 实测记录

开发板：`root@192.168.8.143`

官方程序：

```text
/opt/bestmow/native_camera/releases/20260820-x5-native-v1/build-x5/bin/camera_shared_test
```

配置：1088×1280、30 FPS、SC132GS V2 GDC、API index 1/0。

结果：

1. 使用非法 API index 4 的单目测试：失败，`Unsupported sensor index 4`。
2. 修正为 API index 1 的单目测试：索引和 GDC 映射正确，但反复失败于
   `create_isp_node(951) failed, ret -10`，随后 `camera wait ready failed`。
3. 停止并 mask `S90cam-service.service`、`bestmow-stereo-h264.service`、
   `camera-preview.service` 后重试，仍为 `ret=-10`。
4. 重启板卡后，仅停止相机服务并执行 5 秒单目诊断，仍为 `ret=-10`。

内核日志同时出现：

```text
vs-isp 3d000000.isp: failed to call isp_set_state (err=-22)
vs-isp 3d000000.isp: failed to post off state changed (err=-22)
```

这表明当前问题是 ISP/VIN 驱动状态或资源释放流程，不是 ROS2 节点、VPU 或
StereoSGBM 算法问题。
