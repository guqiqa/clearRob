## 1. 模块定位与职责边界

### 1.1 定位

`master_controller` 是系统的"大脑"，承担四个核心职责：
1. **任务调度**：接收归一化指令，转化为对各模块的任务下发
2. **状态机管理**：运行自动巡航状态机，维护清扫生命周期
3. **运动指令仲裁**：在多源运动指令中选择最终执行指令
4. **系统异常处理与降级**：监控各模块健康度，执行降级/安全策略

### 1.2 职责边界

| 属于本模块 | 不属于本模块 |
|-----------|-------------|
| 归一化指令 → 任务调度决策 | 指令的归一化翻译（control_gateway 负责） |
| 自动巡航状态机运行 | 路径的具体计算（path_planner 负责） |
| 多源运动指令仲裁 | 底盘驱动执行（motion_controller 负责） |
| 清扫生命周期管理 | 清扫机构动作执行（cleaning_actuator 负责） |
| 系统健康监控与降级决策 | 各模块自身的故障检测（各模块自行检测，本模块汇总决策） |
| 电池/电量管理（暂兼管） | — |

## 2. ROS2 接口规范

### 2.1 Node 信息

| 项目 | 内容 |
|------|------|
| ROS2 Node | `master_controller` |
| 命名空间 | `/`（全局） |
| 语言 | C++17（状态机实时性 + Action 客户端） |
| 生命周期 | ROS2 Managed Lifecycle |
| 多线程 | 2 个回调组：主状态机（MutuallyExclusive）+ 运动仲裁（Reentrant，高频） |

### 2.4 Action Client（调用其他模块）

| Action | 调用时机 | 说明 |
|--------|---------|------|

| Service | 类型 | 说明 |
|---------|------|------|

## 3. 自动巡航状态机

### 3.1 状态定义

| 状态编号 | 状态名 | 说明 | 允许的操作 |
|---------|--------|------|-----------|
| S0 | `STANDBY` | 待命中：充电完成 / STOP 指令后停留 | 接收 START / MANUAL / RETURN |
| S1 | `PLANNING` | 路径规划中：已设定区域，等待 path_planner 计算 | 接收 PAUSE / STOP / ESTOP |
| S2 | `CRUISING` | 巡逻巡航：沿路径扫描，检测到垃圾则转清扫 | 接收 PAUSE / STOP / RETURN / ESTOP |
| S3 | `CLEANING` | 定点清扫：执行清扫动作，视觉反馈验证 | 接收 PAUSE / STOP / ESTOP |
| S4 | `PAUSED` | 暂停：保持定位不丢失，机构停止 | 接收 RESUME / STOP / RETURN / ESTOP |
| S5 | `RETURNING` | 返航：返回充电站 | 接收 ESTOP（不接收其他指令，除非紧急） |
| S6 | `CHARGING` | 充电中：已到达充电站并接入 | 接收 START（充电完成自动触发） |
| S7 | `ESTOP` | 急停：所有运动/清扫机构停止 | 仅接收急停解除信号 |

### 3.2 状态转移详述

```
                    ┌──────────┐
                    │  S0      │
                    │  STANDBY │ ← 上电初始化 / STOP 指令 / 充电完成自动触发
                    └────┬─────┘
            START↓         ↓ RETURN
                    ┌──────┴──────┐          ┌──────────┐
                    │  S1         │          │  S5      │
                    │  PLANNING   │          │ RETURNING│
                    └──────┬──────┘          └────┬─────┘
              PlannerState=READY↓          到达↓
                    ┌──────┐          ┌──────────┐
               ┌──→│  S2  │          │  S6      │
               │   │CRUISE│          │ CHARGING │
               │   └──┬───┘          └──────────┘
               │ 检测到垃圾↓
               │   ┌──────┐
               │   │  S3  │
               │   │CLEAN │
               │   └──┬───┘
               │ 清扫完成↓
               └── 回归 S2 ──┘
```

### 3.3 转移触发条件

每条转移定义：**{当前状态, 触发事件, 目标状态, 附加动作}**

| # | 当前 | 触发事件 | 目标 | 附加动作 |
|---|------|---------|------|----------|
| T1 | S0 | START 指令 | S1 | 发送 `master/task/mode(mode=CRUISE)` → vision_detector, lidar_perception, path_planner |
| T2 | S0 | RETURN 指令 | S5 | 调用 `planner/navigate_to_goal`（目标=充电站位置），发送 `master/task/mode(mode=RETURN)` |
| T3 | S1 | `planner/status/state=READY` | S2 | 调用 `motion/follow_path` 执行路径跟踪 |
| T4 | S1 | PAUSE 指令 | S4 | 取消 `planner/navigate_to_goal` Action；发送 `master/cmd/motion` 零速指令 |
| T5 | S1 | STOP 指令 | S0 | 同上取消 + 发送 `master/task/mode(mode=STANDBY)` |
| T6 | S1 | ESTOP | S7 | 运动急停（见转移 T18） |
| T7 | S2 | vision/detect/list 检测到垃圾 (count>0) | S3 | 暂缓 follow_path；发送 `master/task/clean_strategy(strategy=SPOT)`；调用 `cleaning/execute_cleanup` |
| T8 | S2 | PAUSE 指令 | S4 | 暂停 follow_path；发送 `master/cmd/motion` 零速指令 |
| T9 | S2 | STOP 指令 | S0 | 取消 follow_path；发送 `master/task/mode(mode=STANDBY)` |
| T10 | S2 | RETURN 指令 / 低电量(≤15%) / 尘满 | S5 | 取消 follow_path；调用 `planner/navigate_to_goal`（目标=充电站） |
| T11 | S2 | ESTOP | S7 | 见 T18 |
| T12 | S3 | cleaning/execute_cleanup 完成 + cleanliness ≥ 0.7 | S2 | 恢复 follow_path；发送 `master/task/clean_strategy(strategy=IDLE)` |
| T13 | S3 | cleanliness < 0.7 连续 3 次 | S3 | 保持 S3，重新调用 `cleaning/execute_cleanup`（重扫） |
| T14 | S3 | PAUSE 指令 | S4 | 取消 `cleaning/execute_cleanup` Action；清扫机构停止 |
| T15 | S3 | STOP 指令 | S0 | 同 T9 |
| T16 | S3 | ESTOP | S7 | 见 T18 |
| T17 | S3 | RETURN / 低电量 / 尘满 | S5 | 取消 `cleaning/execute_cleanup`，然后同 T10 |
| T18 | S4 | RESUME 指令 | 返回暂停前状态 | 恢复暂停前操作（follow_path 或 execute_cleanup） |
| T19 | S4 | STOP 指令 | S0 | 发送 `master/task/mode(mode=STANDBY)` |
| T20 | S4 | RETURN 指令 | S5 | 同 T10 |
| T21 | S5 | `planner/status/state=COMPLETED`（到达充电站） | S6 | 发送 `master/task/mode(mode=STANDBY)` |
| T22 | S5 | ESTOP | S7 | 见 T18 |
| T23 | S6 | 充电完成（电量≥95%）+ START 指令 | S0 | 自动转入 STANDBY 等待 START |
| T24 | S6 | START 指令（电量≥30%） | S1 | 允许低电量启动短任务 |
| T25 | S7 | ESTOP 解除 | S0 | 系统复位至 STANDBY |
| T26 | 任意 | motion/status/fault(requires_reset=true) | S7 | 紧急停止所有机构 |
| T27 | 任意 | fusion/3d_target(alert_level=CRITICAL) | S4 | 紧急暂停等待人工判断 |
| T28 | 任意 | localization/confidence < 0.3 持续 5s | S4 | 定位丢失暂停 |

## 4. 运动指令仲裁

### 4.1 仲裁规则

```
仲裁优先级（高→低）：
  1. control/cmd/estop（硬直达 motion_controller，不参与仲裁）
  2. control/cmd/manual_velocity（遥控/App 直接运动指令，MANUAL 模式）
  3. planner/cmd/maneuver（路径规划操控指令）
```

### 4.2 仲裁流程（每收到一个运动指令执行一次）

```
输入: 最新手动速度 Twist_manual (可能为空)
      最新 maneuver 指令 Twist_planner (可能为空)
      当前模式 state

1. 如果 state == S7 (ESTOP):
      发布 MotionCommand(estop=true, linear=0, angular=0)

2. 如果 state == S5 (RETURNING) 或 S3 (CLEANING):
      使用 planner/cmd/maneuver（路径跟踪中，不接受手动接管）

3. 如果 Twist_manual 不为空 且 来源=遥控器 且 state 允许手动:
      使用 Twist_manual → MotionCommand(estop=false, linear, angular)

4. 如果 Twist_planner 不为空:
      使用 Twist_planner → MotionCommand(estop=false, linear, angular)

5. 如果两个都为空:
      发布 MotionCommand(一切为零) — 静止保护
```

### 4.3 输出限制

运动指令发布前通过限幅：
- `|linear_velocity| ≤ max_linear_velocity`（默认 1.5 m/s）
- `|angular_velocity| ≤ max_angular_velocity`（默认 2.0 rad/s）
- 加速限制：`|Δlinear| ≤ max_linear_accel × Δt`（默认 max_accel=1.0 m/s²）
- 角加速限制：`|Δangular| ≤ max_angular_accel × Δt`（默认 max_accel=2.0 rad/s²）

## 5. 清扫生命周期管理

### 5.1 清扫区域设定

```
App 在移动端地图选点/画区 → SET_AREA 指令 → master_controller
                                                 │
                                          创建 TaskArea 消息
                                          (area_id=UUID, boundary=多边形)
                                                 │
                                    master/task/area → path_planner
                                                 │
                                    调用 planner/navigate_to_goal
```

### 5.2 清扫→验证→重扫 闭环

```
1. vision_detector 检测到垃圾 (count > 0)
2. master_controller 决定进入 CLEANING (S3)
3. 发送 CleanStrategy(strategy=SPOT) → cleaning_actuator
4. 调用 cleaning/execute_cleanup Action
5. 清扫过程中持续监控 vision/detect/cleanliness
6. cleanliness ≥ 0.7 → 清扫完成 → 恢复 CRUISING
7. cleanliness < 0.7 连续 3 次 (间隔 1Hz) → 判定重扫 → 重新执行步骤 4
```

### 5.3 多区域清扫

如果 App 一次下发多个区域（params[] 含多个 area_id）：
- 按 TSP 排序各区域（由 path_planner 计算访问顺序）
- 逐区域执行：区域 1 PLANNING→CRUISING→(CLEANING if needed)→区域 2 ...
- 全部区域完成 → 发送任务完成状态

## 6. 异常处理与降级

### 6.1 模块故障降级矩阵

| 故障模块 | 触发条件 | 降级动作 | 恢复条件 |
|----------|---------|----------|----------|
| vision_detector | heartbeat 超时 > 5s 或 status=2 | 关闭垃圾触发清扫（仅巡航不扫）；fusion_engine 进入纯 LiDAR 避障 | heartbeat 恢复 + status=0/1 持续 10s |
| lidar_perception | heartbeat 超时 > 5s | 禁止所有运动，转入 S4 PAUSED（安全优先） | heartbeat 恢复 |
| path_planner | PlannerState=BLOCKED 或 heartbeat 超时 | 发送零速指令，转入 S4 | PlannerState 恢复 READY/EXECUTING |
| motion_controller | FaultStatus(requires_reset=true) | 转入 S7 ESTOP | fault 清除 + 手动 RESUME |
| localization_engine | confidence < 0.3 持续 5s | 转入 S4；仅允许 MANUAL 操控 | confidence > 0.6 持续 3s |
| cleaning_actuator | heartbeat 超时 | 标记清扫不可用，仅执行巡航不扫 | heartbeat 恢复 |
| fusion_engine | heartbeat 超时 | 使用 lidar/obstacle/list 直接避障（不依赖融合决策） | heartbeat 恢复 |
| control_gateway | heartbeat 超时 > 5s | 立即转入 S4（无指令来源） | heartbeat 恢复 |

### 6.2 低电量处理

| 电量阈值 | 状态限制 | 动作 |
|----------|---------|------|
| >30% | 全功能 | 正常调度 |
| 30%→15% | 限制新任务 | 禁止开始新清扫区域，完成当前区域后自动 RETURN |
| ≤15% | 仅返航 | 强制触发 RETURN，中断当前所有任务，不可被 PAUSE/RESUME 中断 |
| ≤5% | 紧急模式 | 系统最低功耗运行，仅维持 SLAM 定位和底盘驱动，其余模块关闭 |
| ≤5% + 到达充电站 | 正常充电 | 转入 CHARGING |

### 6.3 融合告警处理

`fusion/3d_target(alert_level=CRITICAL)` 触发：
1. 如果是行人/宠物快速靠近（alert_reason 包含 "approaching"） → S4 PAUSED，等待 5s 后自动恢复
2. 如果是不可通过障碍物 → 向 path_planner 发送 SET_AREA（重新规划绕行）
3. 连续 CRITICAL 超过 30s → 停止当前任务，转入 S4，等待人工介入

## 7. 配置参数（ROS2 Parameter YAML）

```yaml
master_controller:
  ros__parameters:
    # 运动限制
    max_linear_velocity: 1.5              # 最大线速度 m/s
    max_angular_velocity: 2.0             # 最大角速度 rad/s
    max_linear_accel: 1.0                 # 最大线加速度 m/s²
    max_angular_accel: 2.0                # 最大角加速度 rad/s²
    
    # 仲裁
    arbitration_rate: 50.0                # 仲裁循环频率 Hz
    maneuver_timeout_s: 0.2               # planner/cmd/maneuver 超时 (s)，超时后置零速
    
    # 清扫
    cleanliness_pass_threshold: 0.7       # 清洁度合格阈值
    max_resweep_count: 3                  # 最大重扫次数（超过后放弃该区域）
    
    # 电池
    battery_warn_threshold: 0.3           # 低电量告警阈值
    battery_force_return_threshold: 0.15  # 强制返航阈值
    battery_emergency_threshold: 0.05     # 紧急省电阈值
    battery_full_threshold: 0.95          # 满充判断阈值
    
    # 定位
    localization_confidence_min: 0.3      # 最小定位置信度
    localization_degrade_timeout_s: 5.0   # 定位丢失判定超时
    
    # 模块监控
    heartbeat_timeout_s: 5.0              # 心跳超时判定 (s)
    recovery_hold_s: 10.0                 # 故障恢复后保持观察时长 (s)
    
    # 融合告警
    critical_alert_auto_resume_s: 5.0    # CRITICAL 告警自动恢复等待
    critical_alert_max_duration_s: 30.0  # CRITICAL 持续上限（超时人工介入）
```

## 8. 关键交互序列

### 8.1 完整清扫任务流

```
App(SET_AREA) → control_gateway → control/cmd/unified
                                        │
                                  master_controller
                                        │
                              ┌─────────┼─────────┐
                              ↓         ↓         ↓
                    master/task/mode  master/task/area  planner/navigate_to_goal
                    (CRUISE)          (区域多边形)      (Action: 发起导航)
                    → vision_detector → path_planner    → path_planner
                    → lidar_perception
                    → path_planner
                              │              │
                              │    planner/output/path (路径就绪)
                              │              │
                              │    motion/follow_path (Action: 执行路径跟踪)
                              │              │
                              │    planner/cmd/maneuver (持续操控指令)
                              │              │
                              │    master/cmd/motion (仲裁后) → motion_controller
                              │              │
                    vision/detect/list (检测到垃圾)
                              │
                    master/task/clean_strategy (SPOT)
                              │
                    cleaning/execute_cleanup (Action: 执行清扫)
                              │
                    vision/detect/cleanliness (≥0.7 合格)
                              │
                    master/task/clean_strategy (IDLE)
                              │
                              ↓
                    恢复 CRUISING → 下一区域
```

### 8.2 异常降级恢复流

```
localization_engine → localization/confidence (0.25)
     │
     ├── t=0-5s: master_controller 记录低置信度
     │
     ├── t=5s: 判定定位丢失
     │         转入 S4 PAUSED
     │         发送 system/alert(severity=WARN, alert_code="LOCALIZATION_LOW")
     │         保留最后已知位姿
     │         发送零速指令
     │
     ├── t=5-10s: localization/confidence 恢复至 0.65
     │
     └── t=10s: recovery_hold_s 到期
                转入暂停前状态 (S2 CRUISING)
                恢复 follow_path
                发送 system/alert(severity=INFO, "LOCALIZATION_RECOVERED")
```

## 9. 开发里程碑

| 阶段 | 内容 | 交付物 |
|------|------|--------|
| M1: 状态机 | 状态机框架 + 指令响应 + 状态转移 | 状态机可运行 |
