# 双目取流阶段一部署记录

更新时间：2026-08-24

## 当前正式链路

`S90cam-service.service` 是唯一相机采集所有者，`bestmow-stereo-h264.service` 提供左右 H.264。`video_input` 不再打开 H.264 URL，只消费 ROS2 图像话题并转发给视觉识别和双目测距模块。

当前已验证的 ROS2 取流入口是 `s90_h264_input`：两路分别订阅 `/left.h264` 和 `/right.h264`，使用单线程 OpenCV 解码，输出 `544x640 mono8`，默认 5 FPS。它只用于取流验证和阶段一回退，不改变 S90 的启动方式。

## VPU 加速状态

新增 `s90_vpu_input` C++ 包，已在开发板使用 Hobot SDK 和 `libmultimedia.so.1` 编译成功。运行时 MediaCodec 报告 `vdec_render isn't ready`，并触发底层段错误，因此 `enable_vpu` 默认设置为 `false`，服务未启用。不得在未修复该驱动初始化问题前反复启动 VPU 节点。

NPU/BPU 不用于 H.264 解码；后续只给视觉识别模型使用。传统 StereoSGBM 仍使用 CPU。

开发板诊断显示 `/dev/vpu` 和 `hobot_vpu` 均存在，但设备树中的 `vpu_v4l2@3B000000/status` 为 `disabled`，系统没有 `/dev/video*` 解码节点。`s90_vpu_input` 现在会先检查该状态，未启用时拒绝调用 MediaCodec，避免触发 `vdec_render` 段错误。

## 阶段一操作

```bash
systemctl is-active S90cam-service.service bestmow-stereo-h264.service camera-preview.service
systemctl is-enabled native-stereo-camera.service bestmow-s100p-sender.service
source /opt/ros/humble/setup.bash
source /root/cleaning_robot_ws/install/setup.bash
ros2 launch s90_h264_input stereo.launch.py
```

验收时使用独立 ROS2 订阅脚本统计左右帧数、尺寸、编码、时间戳和 CPU/RSS。阶段一通过前保持 `stereo_depth`、RTAB-Map 和 `s90-vpu-input.service` 停止。

阶段一通过后，使用 `ROS2-clearRob/src/stereo_depth/tools/calibrate_stereo.py` 在本机离线标定：

```bash
python ROS2-clearRob/src/stereo_depth/tools/calibrate_stereo.py \
  --left-dir calib/left --right-dir calib/right \
  --output calib/stereo_544x640.yaml \
  --cols 7 --rows 10 --square-size-m 0.02 --min-pairs 20
```

左右图像文件名应一一对应。工具输出 `K/D/R/T/R1/R2/P1/P2/Q`、RMS 和实际基线，格式与 `stereo_depth` 读取逻辑一致；正式采集目标是至少 30 对有效棋盘图。

## 回退与恢复

```bash
pkill -TERM -x s90_vpu_input_node
pkill -TERM -x s90_h264_input_node
systemctl restart S90cam-service.service bestmow-stereo-h264.service
```

VPU 驱动问题修复后，先单目启用 `enable_vpu:=true` 做 15 秒测试，再进行双目同步压测；不得直接启用 systemd 常驻服务。
